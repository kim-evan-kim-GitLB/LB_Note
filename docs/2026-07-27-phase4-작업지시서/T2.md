## T2. 운영 알림 채널 — `src/web/slack_notify.py` (발신 전용 Slack 알림 + 영속 쿨다운)

**목표**: 이미 감지되고 있으나 audit 로그·admin 화면에만 남는 운영 이벤트(STT 스톨, 자격증명 무효화, DB 백업 실패, 헬스 degraded 전이)를 Slack 채널로 밀어낸다. 웹 프로세스가 재기동돼도 동일 이벤트가 재발송되지 않도록 쿨다운 상태를 디스크에 영속화하고, 발송이 서비스 스레드/이벤트 루프를 절대 블로킹하지 않게 한다.

**우선순위 / 예상 공수**: P0 / 10~14h (코드 6h, 단위테스트 4h, env·문서 2h)

**선행 조건**
1. **[선행 T1-2 필수]** T1 헬스 심화 PR(`feature/171-health-buildinfo`)이 main 에 머지돼 있어야 한다. 인터페이스 소유권상 **`_health_snapshot() -> dict` 는 T1 의 산출물**이다 — T1 이 `src/web/app.py` 에서 판정 로직을 모듈 함수로 추출하고, 라우트 `health()`(실측 `app.py:3252`)는 그 함수를 감싸 HTTP 코드만 담당한다. T2 는 이 함수를 **소비만** 한다(정의·수정 금지). 반환 dict 에는 최소한 `"status": "ok"|"degraded"` 와 판정 사유 키(`reasons`)가 있어야 하며, `health_degraded` 이벤트의 유일한 소스다. 현재 `health()` 는 `"ok": True` 상수(실측 `app.py:3257`)라 전이 판정 소스가 없다.
2. **[사용자 수행]** 라이브 컨테이너에 토큰 실주입 확인: `docker exec meetscript-171 sh -c 'echo ${SLACK_BOT_TOKEN:0:5}'` 가 `xoxb-` 로 시작.
3. **[사용자 수행]** 토큰 유효성 확인: `curl -s -H "Authorization: Bearer $SLACK_BOT_TOKEN" https://slack.com/api/auth.test` 의 `ok:true`.
4. **[사용자 수행]** `#lbnote-ops` 채널 생성 + 기존 봇 앱 초대(`/invite @LB Note`). 채널 ID 를 `OPS_ALERT_SLACK_CHANNEL` 에 넣을 값으로 확보.
5. 선행 1이 미충족이면 "막히면" 절의 분기를 따른다(3종만 구현, `health_degraded` 는 별도 후속).

**브랜치**: `feature/171-ops-slack-notify`

**머지 순서와 재동기 규칙**: 실행 순서는 T1 -> T2 -> T3 -> T4/T5 다. T2 착수 전 `git fetch origin && git checkout -b feature/171-ops-slack-notify origin/main` 으로 T1 머지분 위에서 분기한다. 공유 편집 파일은 `deploy/.env.deploy.example` 하나뿐이며(T1·T3·T4·T5 도 각자 줄을 추가한다) T2 는 **아래 명시한 5줄만** 추가한다. `deploy/docker-compose.yml` 은 T1(image 태그·build args·healthcheck)·T3(미러 바인드)·T4(logging)의 소관이라 T2 는 **건드리지 않는다**.

### 구현 단계

1. **`src/web/slack_notify.py` 골격**
   - 모듈 docstring 에 이벤트 사전(아래 표)을 한글로 기록한다. 이 docstring 이 T7 런북 **14장 "알림 이벤트 사전과 대응자"** 의 원본이다. **신규 docs 파일은 만들지 않는다**(위치 확정 전).
   - 이벤트 카탈로그 상수:

     | 이벤트 키 | 심각도 | 트리거 | 발송 소유 |
     |---|---|---|---|
     | `stt_stalled` | WARN | `_scan_stt_stalls` 가 신규 스톨 마킹 | T2 |
     | `cred_invalid` | WARN | 스윕에서 `valid True->False` 또는 `decrypt_failed` 신규 전이 | T2 |
     | `backup_failed` | ERROR | `maintenance._notify_backup_failed()` 호출(예외 또는 스냅샷 미생성) | T2(함수) / 호출부 확장은 T3 |
     | `health_degraded` / `health_recovered` | ERROR / INFO | T1 의 `_health_snapshot()["status"]` 전이 | T2 |
     | `disk_high` | WARN/ERROR | 디스크 워터마크 초과 | **T5** (T2 는 카탈로그 정의만, 트리거 배선 금지) |

   - `disk_high` 는 카탈로그(문자열·심각도·메시지 포맷)만 T2 가 적는다. 임계 판정(`classify_disk`)·발송 배선·`_health_snapshot()` 의 `reasons` 편입은 전부 **T5** 소관이다. 따라서 T2 머지 시점에는 디스크가 임계를 넘어도 `health_degraded` 가 발화하지 않는 것이 정상이며, 그 연결은 T5 머지로 완성된다 — 이 사실을 카탈로그 docstring 에 1줄로 명시해 T7 14장이 거짓 보증을 옮겨 적지 않게 한다.

2. **설정 로딩** (모두 `os.environ` 직접 읽기, 모듈 전역):
   - `SLACK_BOT_TOKEN`(기존 변수 재사용), `OPS_ALERT_SLACK_CHANNEL`(기본 `""`)
   - `WEB_OPS_ALERT_COOLDOWN_SEC`(기본 `3600`), `WEB_OPS_ALERT_TIMEOUT_SEC`(기본 `5`)
   - `WEB_OPS_ALERT_MAX_PER_SWEEP`(기본 `5`), `WEB_OPS_ALERT_RUNBOOK_URL`(기본 `""`)
   - `WEB_OPS_ALERT_ONCALL`, `WEB_OPS_ALERT_BACKUP_ONCALL`(기본 `""` — 지명 미정, 빈값이면 해당 줄 생략)
   - `is_enabled() -> bool`: 토큰과 채널이 **둘 다** 있을 때만 True. **미설정 시 RuntimeError 를 던지지 않는다** — `src/slack_bot/config.py:36` `validate()` 와 달리 웹 프로세스 기동을 절대 막지 않는다(봇은 전용 프로세스라 강제 검증이 맞지만 웹은 아니다).

3. **영속 쿨다운**
   - 상태 파일 경로 `_state_path()`: `Path(_storemod.DEFAULT_DB_PATH).parent / "ops_alert_state.json"`. `src/web/audio_store.py:72 audio_base()` 와 동일한 규약(매 호출 시 현재 `DEFAULT_DB_PATH` 를 읽음) -> `tests/conftest.py` 의 세션 픽스처가 임시 경로로 패치하므로 테스트 격리가 자동으로 성립한다. **하드코딩 금지.**
   - 형식: `{"<쿨다운키>": <epoch_float>}`. 기본 쿨다운 키는 `"<이벤트키>:<대상ID>"` 이고 대상 ID 는 job id / username / `"-"`(전역).
   - `_should_send(key) -> bool`: `threading.Lock` 보유 상태에서 파일 로드 -> 마지막 발송 시각과 `time.time()` 비교 -> 통과 시 즉시 기록 후 원자 쓰기(`tmp` 파일 + `os.replace`). 파일 파손(JSONDecodeError)·IO 실패는 삼키고 "발송 허용"으로 폴백한다(알림 유실보다 중복이 낫다).
   - 시각 기준은 `time.monotonic()` 이 아니라 **`time.time()`** 이어야 한다(재기동 후에도 유효해야 하므로).
   - 만료 항목(마지막 발송 + 쿨다운 * 10 초과)은 쓰기 시점에 정리해 파일이 무한 증식하지 않게 한다.

4. **비블로킹 발송**
   - 모듈 전역 `queue.Queue()` + `threading.Thread(daemon=True)` 발송 워커 1개. 워커는 `_dispatch(payload)` -> `_post_message(channel, text)` 를 호출하고 마지막에 반드시 `task_done()`.
   - 워커 스레드는 첫 `notify()` 호출 시 지연 기동(`_ensure_worker()`, `observability._ensure_handler` 와 동일한 1회 부착 패턴).
   - **시그니처(소유자 T2, 이후 지시서는 이 형태만 호출한다)**:
     `notify(event, *, target="-", text="", severity=None, cooldown_sec=None, cooldown_key=None, **fields) -> dict`
     - `cooldown_key` 는 T5 를 위한 오버라이드다. 미지정이면 `f"{event}:{target}"` 을 쓰고, 지정되면 그 문자열을 그대로 쿨다운 키로 쓴다 — T5 는 `disk_high:{name}:{level}` 를 넘겨 `warn -> error` 승격 시 쿨다운을 통과시킨다. T2 는 이 파라미터를 구현하고 단위테스트로 덮되 `disk_high` 트리거 자체는 배선하지 않는다.
     - 반환 `{"queued": bool, "reason": "disabled"|"cooldown"|"queued"}`.
     - 순서: `is_enabled()` 확인 -> `_should_send()` -> 메시지 조립 -> enqueue. **호출자는 어떤 경우에도 HTTP 를 기다리지 않는다.**
     - `_scan_stt_stalls`(동기, `_stt_stall_watchdog_loop` 이 `to_thread` 없이 직접 호출: `app.py:1059-1066`)에서 호출해도 이벤트 루프가 막히지 않는 것이 이 구조의 목적이다. 호출부에 별도 `to_thread` 를 추가하지 않는다.
   - `_post_message`: `urllib.request.Request("https://slack.com/api/chat.postMessage", ...)`, `Authorization: Bearer <token>`, `Content-Type: application/json; charset=utf-8`, `urlopen(req, timeout=WEB_OPS_ALERT_TIMEOUT_SEC)`.
     - 응답 JSON 의 `ok` 가 False 면 `observability.audit("ops_alert.error", event=..., slack_error=<error 코드>)` — `not_in_channel`·`channel_not_found`·`invalid_auth` 가 그대로 보이게 한다("알림이 안 나가는 것" 자체를 관측 가능하게).
     - 성공 시 `observability.audit("ops_alert.sent", event=..., severity=...)`.
     - 모든 예외(`URLError`/`HTTPError`/타임아웃/JSON 파손)를 삼키고 `ops_alert.error` audit 만 남긴다. **토큰·채널ID 원문을 audit 에 싣지 않는다**(`observability.audit` docstring 의 비밀 금지 규약).
5. **메시지 포맷** (한글, 비밀 금지, ASCII 안전 기호만 — 화살표는 `->`):
   ```
   [ERROR] LB NOTE backup_failed
   DB 스냅샷 생성 실패 (source=primary reason=OSError)
   host=meetscript-171 at=2026-08-06T21:03:11
   runbook: <WEB_OPS_ALERT_RUNBOOK_URL>#backup-failed
   1차: <ONCALL> / 대체: <BACKUP_ONCALL>
   ```
   - `runbook`/`1차` 줄은 해당 env 가 빈값이면 통째로 생략한다(G6 요건이나 지명은 unresolved-6).
6. **테스트 훅**: `flush(timeout: float = 5.0) -> bool`(큐 소진 대기, 테스트 전용), `reset() -> None`(큐·인메모리 상태·상태 파일 삭제, `observability.reset()` 과 동일한 테스트 격리 규약). 두 함수 docstring 에 "테스트 전용"을 명시한다.
7. **훅 배선 — `stt_stalled`** (`src/web/app.py` `_scan_stt_stalls` 의 `for s in newly:` 루프 안, `_jobs_lock` **밖**. 실측 1048~1055):
   ```python
   slack_notify.notify("stt_stalled", target=s["job"],
                       text=f"STT 잡이 {s['elapsed_sec']:.0f}s 동안 transcribing 에서 멈춤",
                       owner=s["owner"], marked_error=STT_STALL_MARK_ERROR)
   ```
   `newly` 는 이미 최초 탐지분만 담으므로(`if not already`, 실측 1047) 30초 폭주는 발생하지 않는다. 쿨다운의 실제 목적은 **프로세스 재기동 시 재발송 억제**임을 주석에 남긴다.
8. **훅 배선 — `cred_invalid`** (`_sweep_credential_health`, 705~721):
   - 루프 안에서 `_evaluate_credential_health(username)` **호출 전**에 `with _cred_health_lock: prev = dict(_claude_cred_health.get(username) or {})` 로 이전 상태를 캡처한다. 현재 함수가 캐시를 in-place 갱신하므로(실측 `app.py:671-672`) 사후 비교가 불가능하다.
   - 전이 조건: `prev.get("valid") is not False and new["valid"] is False`. 즉 최초 등록 직후 invalid, `True->False`, `None->False` 를 잡고 `False->False` 반복은 무시한다.
   - 전이한 사용자를 리스트로 모아 스윕 종료 후 발송한다. 사용자당 쿨다운 키(`target=username`)를 쓰되 한 스윕당 최대 `WEB_OPS_ALERT_MAX_PER_SWEEP` 건만 보내고 초과분은 마지막 메시지에 `외 N명` 으로 합친다(57명 규모 동시 만료 시 폭주 방지 — 개발 DB users 57행 실측).
   - **`GET /api/settings/claude-credential/verify`(실측 `app.py:753`) 와 `_mark_cred_health_invalid`(실측 `app.py:689`) 에는 알림을 붙이지 않는다.** 사용자 재인증 클릭·잡 실패마다 관리자에게 WARN 이 나가는 것을 막는다. 이 금지 사유를 두 함수의 docstring 아래 주석 1줄로 남긴다.
9. **훅 배선 — `backup_failed`** (`src/web/maintenance.py`) — **반환 계약 불가침 / 시그니처 소유자 = T2**:
   - `maintenance.py` 에 발송 단일 통로를 신설한다. **아래 시그니처가 확정형이며 T2 가 소유한다** — `source` 는 위치 인자, `reason` 은 keyword-only 다. T3 는 이 함수를 `source="primary"|"mirror"` 로 **호출만** 하고 재정의하지 않는다:
     ```python
     def _notify_backup_failed(source: str, *, reason: str) -> None:
         """DB 백업 실패 알림의 유일한 발송 통로. source 는 'primary' 또는 'mirror'(T3).

         지연 import + 예외 삼킴 — 알림 계층 고장이 백업 경로를 죽이지 않는다.
         """
         try:
             from . import slack_notify
             slack_notify.notify("backup_failed", target=source,
                                 text=f"DB 스냅샷 생성 실패 (source={source} reason={reason})",
                                 severity="ERROR", source=source, reason=reason)
         except Exception:  # noqa: BLE001
             pass
     ```
     `slack_notify` 는 `maintenance` 를 임포트하면 안 된다(순환). 위 지연 import 가 그 방향을 강제한다.
   - `run_db_backup` 의 `except` 블록(실측 109~111)에서 기존 `observability.audit("db_backup.error", ...)` 직후 `_notify_backup_failed("primary", reason=type(e).__name__)` 한 줄만 추가한다. `return {"file": None, "removed": 0}` 리터럴은 **그대로 둔다**.
   - 스냅샷 미생성 방어: `store.backup_to(dest)` 성공 후 `dest.exists()` 와 `dest.stat().st_size > 0` 을 확인하고 거짓이면 `_notify_backup_failed("primary", reason="missing_snapshot")` 후 **기존 except 경로와 동일한 리터럴**로 조기 반환한다. 새 키를 추가하거나 기존 키 이름·의미를 바꾸지 않는다.
   - **T2 는 `run_db_backup` 의 시그니처와 반환 dict 를 확장하지 않는다.** 반환 계약 확장(mirror* 키 추가)은 T3 소관이며, T3 는 기존 2키(`file`/`removed`)를 보존한 채 키만 덧붙인다. T2 의 테스트는 반환 dict 를 단언하지 않는다(아래 수용 기준 참조) — 그래야 T3 머지 후에도 T2 테스트가 깨지지 않는다.
   - **이중 발송 금지**: 백업 실패 알림은 `_notify_backup_failed` 만 통과한다. `run_db_backup` 안에서 `slack_notify.notify` 를 직접 호출하지 않는다. T3 의 미러 경로도 같은 함수를 `_notify_backup_failed("mirror", reason=type(e).__name__)` 로 호출한다(위치 인자 2개로 넘기면 keyword-only 위반으로 `TypeError` 다).

- **`chat.postMessage` 가 `not_in_channel`**: 봇이 채널에 없다. 코드 문제가 아니므로 재시도 로직을 넣지 말고 사용자에게 `/invite` 를 요청한다(자동 `conversations.join` 은 추가 스코프가 필요하고 Phase 4 범위 밖이다).
- **쿨다운 기본값(3600s)이 적절한지**: 08-03 지표 리뷰 게이트에서 D1 라이브 30일 운영 지표(STT 실패·스톨 빈도)로 확정하기로 돼 있다. 그 전에는 3600 을 코드 기본값으로 두되 env 로만 조정 가능하게 하고, 코드에 다른 값을 하드코딩하지 않는다.
- **알림 1차 대응자·대체자 이름**: 미지명 상태(unresolved-6)다. 이름을 **지어내지 말 것**. env 가 빈값이면 해당 줄을 생략하는 현재 설계를 유지하고, 지명이 오면 `.env.deploy` 만 고치면 되게 둔다.
- **`cred_invalid` 가 스윕마다 다수 발화**: `WEB_OPS_ALERT_MAX_PER_SWEEP` 로 상한을 두는 것이 설계지만, 실측에서 매 스윕 5건 이상이 반복되면 임계·전이 판정이 아니라 `CRED_ENC_KEY` 손상(`decrypt_failed` 다수)일 가능성이 높다. 알림 튜닝으로 덮지 말고 사용자에게 키 상태 점검을 에스컬레이션한다.
- **T3 가 `_notify_backup_failed` 를 다른 시그니처로 요구한다**: 이 함수의 시그니처 소유자는 T2 다. `def _notify_backup_failed(source: str, *, reason: str) -> None` 를 유지하고 T3 에는 "호출부만 `("primary"|"mirror", reason=...)` 로 맞추라" 고 회신한다. 임의로 `(reason, detail)` 로 바꾸면 T2 수용 테스트(`test_backup_failed_on_exception_and_missing_file`, 시그니처 inspect 판정)가 확정적으로 깨진다. 합의가 안 되면 에스컬레이션하고 코드를 먼저 바꾸지 않는다.
- **T5 가 `cooldown_key` 외의 시그니처 변경을 요구한다**: T2 가 소유자이므로 T5 지시서를 임의로 따르지 말고 에스컬레이션한다. 파라미터 추가는 하위호환(기본값 None)이면 T2 브랜치에서 수용 가능, 반환 형식 변경은 불가.
- **커밋·푸시**: 사용자가 명시 요청할 때만 수행한다. main 직접 커밋 금지, 브랜치명에 `171` 포함, PR 로 병합. 커밋 메시지에는 Phase 4 Jira 키를 포함하되, Atlassian MCP 가 끊겨 있어 키 조회가 불가하므로 **사용자에게 키를 직접 입력받는다**(추측 금지).
