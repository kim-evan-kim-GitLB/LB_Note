## T3. 백업 이중화(DATA_DIR 외부 미러) + 복구 리허설

**목표**: DB 스냅샷 1부를 DATA_DIR 밖의 별도 호스트 마운트(`/app/backup-mirror`)에 추가 저장해 컨테이너 재생성·DATA_DIR 볼륨 사고에서도 스냅샷이 살아남게 하고, 스냅샷에서 users·자격증명·회의를 실제로 되살릴 수 있음을 기계 판정 가능한 리허설로 1회 증명한다.

**우선순위 / 예상 공수**: P0 / 에이전트 6~8h (구현 3h + 테스트 2h + 리허설 스크립트·문서 2h), 별도로 [사용자 수행] 배포·리허설 1~2h

**선행 조건**:
- T0-1 완료(`.gitignore` 에 `deploy/.env.deploy` 등재). 이 지시서는 `deploy/.env.deploy.example` 만 수정하며 `deploy/.env.deploy` 는 절대 커밋 대상에 넣지 않는다. T0 지시서가 아직 없으면 T3 는 `.gitignore` 를 건드리지 않고 진행하되, `deploy/.env.deploy` 를 새로 만들지도 않는다.
- 실행 순서 T1 -> T2 -> T3 이므로 **착수 시 `origin/main` 을 재동기한 뒤 브랜치를 딴다**. T1 이 `deploy/docker-compose.yml`(image 태그·build args·healthcheck)과 `deploy/.env.deploy.example` 을, T2 가 `src/web/maintenance.py`(백업 실패 훅)와 `deploy/.env.deploy.example` 을 이미 고쳐 놓은 상태를 전제로 한다.
- T2(`src/web/slack_notify.py`) 는 **소프트 의존**이다. 발송 연결부는 방어 임포트(`try: from src.web import slack_notify / except Exception: return`)로 작성해 T2 미머지 상태에서도 T3 단독으로 머지·테스트 가능해야 한다. 단 **`_notify_backup_failed` 의 시그니처만은 T2 확정형(`source: str, *, reason: str`)을 그대로 쓴다**(아래 인터페이스 소유권 절).
- 라이브 배포/미러 마운트 생성/시크릿 오프호스트 보관은 [사용자 수행].

**브랜치**: `feature/171-backup-mirror-restore`

### 인터페이스 소유권 (위반 금지)

- **소유권 1줄 요약: `run_db_backup()` 의 시그니처와 반환 dict = T3 소유 / 발송 함수(`_notify_backup_failed`, `slack_notify.notify`) 의 시그니처 = T2 소유.** T3 는 발송 함수를 **호출만** 한다.
- **`maintenance.run_db_backup()` 의 시그니처와 반환 dict 소유자는 T3 다.** 다른 지시서는 이 계약을 바꾸지 않는다.
  - **기존 2키(`file`, `removed`)는 이름·타입·의미를 그대로 보존한다.** T3 는 `mirrorFile`·`mirrorRemoved`·`mirrorError` **3키만 추가**한다. 기존 키 삭제·개명·의미 변경은 금지.
- **백업 실패 알림은 반드시 `maintenance._notify_backup_failed()` 한 함수만 통과한다(발송 통로 단일화).** `run_db_backup` 안에서 `slack_notify` 를 직접 호출하는 코드는 (T2 가 넣었더라도) 이 함수 호출로 일원화한다. 발송 경로가 둘이면 이중 발송이 된다. **단, 이 함수의 시그니처를 정하는 주체는 T3 가 아니라 T2 다** — T3 가 소유하는 것은 "통로를 하나로 유지한다" 는 배선 규약뿐이다.
- **`maintenance._notify_backup_failed()` 의 시그니처 소유자는 T2 이고 확정형은 아래 하나다.**
  `def _notify_backup_failed(source: str, *, reason: str) -> None`
  T3 는 이 시그니처를 **재정의하지 않고, `(reason, detail)` 등 다른 형태로 바꾸지도 않는다.** 호출만 한다. T2 미머지 상태에서만 T3 가 **동일 시그니처 그대로** 신설한다.
- **발송 함수(`slack_notify.notify(...)`) 자체의 시그니처 소유자도 T2 다.** T3 는 호출만 한다. main 재동기 후 T2 의 실제 시그니처가 이 문서의 가정과 다르면 **T2 쪽을 따르고**, 어댑터 코드는 `_notify_backup_failed()` 한 곳에만 둔다.
- **디스크 임계 환경변수(WARN/ERROR 퍼센트, 대상 경로 목록) 소유자는 T5 다.** T3 는 `WEB_DB_BACKUP_MIRROR_DIR` 만 정의하며, T5 가 이를 `disk_targets()` 대상으로 소비한다(T3 는 임계값을 정의하지 않는다).
- **런북 장번호는 사전 배정돼 있다. T3 = `## 8. 백업·복구` 만 신설한다.** 9장(로그 상한)=T4, 10장(디스크 임계·회수)=T5, 11장(회귀 게이트)=T6, 12~14장(스모크·롤백·알림 사전)=T7. 기존 0~7장과 `## 참고` 절은 삭제·재배열·재번호 금지(실측: 현재 파일 278행, 마지막 장이 `## 7.`).
- `deploy/.env.deploy.example` 과 `deploy/docker-compose.yml` 은 T1·T2·T4·T5 도 건드린다. T3 는 **아래 "변경 대상" 에 적힌 줄만** 추가하고, 리베이스 충돌 시 남의 줄을 되돌리지 않는다.

### 구현 단계

1. **`maintenance.db_backup_mirror_dir()` 추가**
   - `os.environ.get("WEB_DB_BACKUP_MIRROR_DIR", "").strip()` 이 빈 문자열이면 `None` 반환(= 미러 비활성 = 현행 동작). 값이 있으면 `Path(...)` 반환.
   - 모듈 상단에 `import os` 추가(현재 `maintenance.py` 임포트는 `datetime`/`shutil`/`Path`/`audio_store`/`observability` 뿐 — `os` 없음).
   - T5 가 `disk_targets()` 에서 이 함수를 재사용한다(T5 는 `os.environ["..."]` 직접 접근 금지). 함수명·반환형(`Path | None`)을 바꾸지 않는다.

2. **`maintenance._prune_mirror_backups(dir_: Path, keep: int) -> int` 추가**
   - 대상은 `re.fullmatch(r"meetings-(\d{8})-\d{6}-\d+\.db", p.name)` 에 매칭되는 파일만. 매칭 안 되는 파일은 절대 건드리지 않는다(1차 경로의 `other.db` 보존 규약과 동일 취지).
   - (a) 날짜 키(`YYYYMMDD`)별로 묶어 각 날짜에서 **이름 최대값 1개만 남기고** 나머지 삭제. (b) 남은 날짜가 `keep` 개를 넘으면 오래된 날짜부터 삭제. `keep` 은 `max(1, keep)` 로 하한 강제(기존 `run_db_backup` 규약과 동일).
   - 반환값은 삭제 개수. `OSError` 는 개별 `try/except` 로 무시(기존 `_prune_old_db_backups` 와 동일).
   - **`_prune_old_db_backups`(1차 경로, `src/web/maintenance.py:71`)는 손대지 않는다.** 그 함수는 정규식이 아니라 `dir_.glob("meetings-*.db")` 를 쓴다(실측 L78) — 이 사실은 10단계(수동 스냅샷 명명 규칙)의 근거이므로 반드시 유지·인지한다.

3. **`maintenance._notify_backup_failed()` 는 T2 소유 시그니처를 호출만 한다**
   - **확정 시그니처(T2 소유, T3 는 변경 금지)**: `def _notify_backup_failed(source: str, *, reason: str) -> None`
     - `source` 는 `"primary"` | `"mirror"` 두 값만 쓴다. `reason` 은 **keyword-only** 이며 값은 예외 타입명(`type(e).__name__`).
     - T3 는 이 함수를 **정의하지 않는다**(아래 미머지 예외 제외). `(reason, detail)` 형태로의 재정의·개명·인자 추가 전부 금지.
   - **T2 가 이미 머지된 경우(정상 경로)**: 함수 본문에 손대지 않는다. `source="mirror"` 가 통과 가능한지만 확인한다(값 화이트리스트가 `"primary"` 로 하드코딩돼 있다면 `"mirror"` 를 허용값에 1줄 추가하는 최소 수정만 허용).
   - **T2 가 `run_db_backup` 의 `except` 블록에서 `slack_notify` 를 직접 호출하고 있다면**, 그 호출만 `_notify_backup_failed("primary", reason=type(e).__name__)` 로 치환한다(이중 발송 방지). **이것이 T3 가 T2 의 구현 코드를 고치는 유일한 허용 범위다**(테스트 쪽 허용 범위는 4단계에 따로 1줄로 한정돼 있다).
   - **T2 가 미머지인 경우에만** T3 가 위 확정 시그니처 **그대로** 함수를 신설한다(T2 는 나중에 이 함수를 그대로 소비한다. 인자 이름·순서·keyword-only 여부를 바꾸면 T2 의 `call_args` 단언이 깨진다).
     - 본문: 방어 임포트(`try: from src.web import slack_notify / except Exception: return`) 후 발송 함수 1회 호출. 발송 예외는 전부 삼키고 `observability.audit("db_backup.notify_error", error=type(e).__name__)` 만 남긴다. **백업 경로가 알림 때문에 죽으면 안 된다.**

4. **T2 가 넣은 1차 백업 실패 분기 보존**
   - T2 는 1차 경로에 "예외 없음 + 스냅샷 파일 미생성" 검사 분기를 추가한다. **T3 는 이 분기를 삭제·완화하지 않는다.** 해당 분기도 아래 5단계의 5키 dict 를 반환하되 `file=None, removed=0` 을 유지한다.
   - **T3 가 T2 테스트를 고치는 허용 범위(정확히 이 1건뿐)**: `tests/test_ops_alerts.py`(또는 T2 가 둔 파일)의 `test_backup_failed_on_exception_and_missing_file` 이 `run_db_backup` 반환 dict 를 **정확 일치**로 단언하는 그 단언문 1줄을 `res["file"] is None and res["removed"] == 0` 형태의 **부분집합 단언**으로 바꾸는 것. **그 외 어떤 T2 테스트도, 같은 테스트의 다른 단언(특히 `_notify_backup_failed` 의 `call_args` 로 `source == "primary"` 를 보는 단언)도 수정·삭제하지 않는다.** 수정 시 PR 설명에 그 사실을 1줄로 남긴다.

5. **`run_db_backup()` 확장** (`src/web/maintenance.py:95`)
   - 시그니처: `run_db_backup(store, *, keep=DEFAULT_DB_BACKUP_KEEP, mirror_dir: Path | None = None, mirror_keep: int = DEFAULT_DB_BACKUP_MIRROR_KEEP) -> dict`. 위치 인자·기존 키워드는 그대로 유지한다.
   - **반환 dict 계약(T3 확정, 이 5키 고정)**:
     - 성공: `{"file": <dest.name>, "removed": <int>, "mirrorFile": <str|None>, "mirrorRemoved": <int>, "mirrorError": <str|None>}`
     - 실패(예외 또는 파일 미생성): `{"file": None, "removed": 0, "mirrorFile": None, "mirrorRemoved": 0, "mirrorError": None}`
     - `file`·`removed` 의 값·의미는 현행과 동일하다. 미러 미설정 시 `mirrorFile=None, mirrorRemoved=0, mirrorError=None`.
   - 1차 백업 실패(기존 `except` 분기, L109~111): `observability.audit("db_backup.error", ...)` 유지 + `_notify_backup_failed("primary", reason=type(e).__name__)` 호출(또는 T2 가 이미 넣은 동형 호출을 **그대로 둠**) 후 위 실패 dict 반환.
   - 1차 성공 후 `mirror_dir` 이 None 이 아니면: `mirror_dir.mkdir(parents=True, exist_ok=True)` -> `mirror_dir.chmod(0o700)`(suppress OSError) -> `shutil.copy2(dest, mirror_dir / dest.name)` -> 사본 `chmod(0o600)`. **`store.backup_to` 를 두 번 호출하지 말 것** — store 락을 두 번 잡아 쓰기 지연을 늘린다. 이어서 `_prune_mirror_backups(mirror_dir, mirror_keep)`.
   - 미러 단계 전체를 `try/except Exception` 으로 감싸 1차 백업 결과를 무효화하지 않는다. 실패 시 `observability.audit("db_backup.mirror_error", error=type(e).__name__)` + `_notify_backup_failed("mirror", reason=type(e).__name__)` + 반환 dict `mirrorError` 에 예외 타입명.
   - 성공 시 기존 `observability.audit("db_backup.run", ...)` 호출에 `mirror=<사본 파일명>`·`mirror_removed=<n>` 필드를 추가한다(**audit 이벤트명 `db_backup.run` 은 바꾸지 않는다** — 동명 카운터가 이미 `/api/admin/metrics` 와 `tests/test_db_backup.py` 에서 단언된다. 코드 주석 L113 도 "별도 incr 금지" 를 명시).
   - **동일 디바이스 경고**: `os.stat(dir_).st_dev == os.stat(mirror_dir).st_dev` 이면 `observability.audit("db_backup.mirror_same_device")` 를 남긴다(예외 아님, 판정용 신호). `OSError` 는 무시.

6. **`app.py` 배선**
   - `DB_BACKUP_KEEP`(L105) 뒤에 추가:
     `DB_BACKUP_MIRROR_DIR = os.environ.get("WEB_DB_BACKUP_MIRROR_DIR", "").strip()`,
     `DB_BACKUP_MIRROR_KEEP = int(os.environ.get("WEB_DB_BACKUP_MIRROR_KEEP", str(maintenance.DEFAULT_DB_BACKUP_MIRROR_KEEP)))`
   - `_db_backup_loop()` 의 호출(L175 `await asyncio.to_thread(maintenance.run_db_backup, store, keep=DB_BACKUP_KEEP)`)에 `mirror_dir=maintenance.db_backup_mirror_dir(), mirror_keep=DB_BACKUP_MIRROR_KEEP` 를 추가한다(`asyncio.to_thread` 는 키워드 인자를 그대로 전달하므로 `functools.partial` 불필요).
   - `/api/admin/metrics` 의 `dbBackup` dict(L3242~)에 `"mirror": {"dir": DB_BACKUP_MIRROR_DIR or None, "keep": DB_BACKUP_MIRROR_KEEP, "count": maintenance.db_backup_mirror_count()}` 추가. 기존 키(`enabled`/`intervalSec`/`keep`/`count`)는 삭제·개명 금지.
   - 앵커는 행번호가 아니라 **심볼명**(`DB_BACKUP_KEEP`, `_db_backup_loop`, `"dbBackup"`)으로 잡는다. 위 행번호는 착수 시점 실측값이며 T1·T2 머지로 밀릴 수 있다.

   - 검사 항목:
     (a) `UserStore.count()`(`src/web/auth.py:475`) -> `usersCount`, `--expect-users` 지정 시 일치 판정.
     (b) `UserStore.list_credential_owners()`(`auth.py:631`) 로 자격증명 보유자를 얻고, 각 username 에 대해 `UserStore.get_credential(u)`(`auth.py:518`) 가 `None` 이 아닌 건수 -> `credsDecrypted`. `get_credential` 은 복호 실패 시 `None` 을 반환하므로 이 값이 곧 decrypt 성공 건수다. **환경변수 `CRED_ENC_KEY` 를 라이브와 동일하게 주고 실행해야 의미가 있다**는 점을 `--help` 와 출력에 명시.
     (c) `MeetingStore.count_meetings()`(`src/web/store.py:436`) -> `meetingsCount`, `--meeting-id` 지정 시 `MeetingStore.get(id)`(`store.py:170`) 가 not None 인지 -> `meetingFetched`.
   - 출력은 한 줄 JSON(`{"snapshot":..., "usersCount":..., "credOwners":..., "credsDecrypted":..., "meetingsCount":..., "meetingFetched":..., "verdict":"pass"|"fail"}`). 판정 실패 시 종료코드 1.

### 하위호환 / 롤백

- `run_db_backup(store, keep=...)` 의 기존 호출 형태는 그대로 동작해야 한다. 새 인자는 전부 키워드 + 기본값이며, `mirror_dir=None` 이면 코드 경로가 현행과 동일하다.
- 반환 dict 의 기존 2키(`file`, `removed`)는 이름·타입·의미가 불변이다. 소비처는 5키 중 필요한 키만 읽으면 되고, 정확 일치 비교를 하는 테스트는 부분집합 비교로 바꾼다(4단계).
- audit 이벤트명 `db_backup.run` / `db_backup.error` 와 `/api/admin/metrics` 의 기존 `dbBackup` 키 4종은 **개명·삭제 금지**(기존 테스트·프론트 소비처가 있다). 추가만 한다.
- `_prune_old_db_backups`(1차 백업 경로)는 손대지 않는다. 미러는 별도 함수 `_prune_mirror_backups` 로만 처리한다.
- 미러 실패는 절대 1차 백업 성공을 무효화하지 않는다. 미러 예외로 `_db_backup_loop` 이 죽어서는 안 된다(루프 자체는 이미 예외를 삼키지만, `run_db_backup` 내부에서 먼저 격리한다).
- compose 롤백: 미러 바인드 1줄과 `WEB_DB_BACKUP_MIRROR_DIR` 환경변수를 제거하고 재기동하면 즉시 현행 동작으로 복귀한다(DB·산출물 영향 없음). 코드 롤백은 브랜치 revert 만으로 충분하며 스키마 변경이 없어 DB 후퇴 이슈가 없다.
- `tools/restore_rehearsal.py` 는 **인자로 받은 스냅샷 원본을 변조하지 않는다**(tempdir 사본 위에서만 `UserStore`/`MeetingStore` 의 스키마 승계 DDL 이 발생한다). "읽기 전용" 이 아니라 "원본 미접촉" 이 정확한 표현이며, 인자 스냅샷 외 어떤 DB 도 열지 않는다.

### 막히면

- **T2 가 미머지라 `slack_notify` 발송 함수의 시그니처를 알 수 없다**: `_notify_backup_failed(source: str, *, reason: str) -> None`(확정형) **껍데기는 그대로 만들고** 본문만 방어 임포트 no-op 로 두어 머지한 뒤, T2 머지 직후 이 함수 **본문 1곳만** 수정하는 후속 커밋으로 연결한다(그 후속 커밋을 T2 의 완료 조건에도 넣는다). **시그니처를 임시로 바꿔 두는 선택지는 없다** — T2 의 `call_args` 단언(`source == "primary"`)이 깨진다. 그래도 애매하면 T2 담당 결정 사항으로 에스컬레이션.
- **main 재동기 후 T2 가 반환 dict 를 이미 바꿔 놓았다**: 강제 소유권 규칙상 반환 계약 소유자는 T3 다. 5단계의 5키 계약으로 되돌리되 T2 가 추가한 **분기·검사 로직은 보존**하고, PR 설명에 "반환 계약 T3 소유, T2 분기 보존" 을 1줄로 남긴다. 판단이 갈리면 진행을 멈추고 에스컬레이션한다(임의로 T2 로직을 지우지 말 것).
- **미러 마운트를 DATA_DIR 과 같은 물리 디스크에만 둘 수 있는 경우**(171 호스트에 별도 마운트가 없음): `db_backup.mirror_same_device` audit 이 뜨는 상태로 진행하되, "볼륨 사고 내성" 은 달성되지 않고 "컨테이너 재생성 내성" 만 달성됨을 런북 8.1 에 명시하고 **사용자에게 별도 디스크/NAS 확보 여부를 질의**한다. 하드웨어 조달 판단이라 에이전트가 정할 수 없다.
- **미러 keep=30 이 용량을 초과**: 스냅샷 1개 크기 x 30 + `predeploy-*.db` 누적분이 미러 파티션 여유를 넘으면 `WEB_DB_BACKUP_MIRROR_KEEP` 를 낮춘다. 실제 스냅샷 크기는 D1 라이브 지표 스냅샷에서 확인되므로 08-03 지표 리뷰 게이트에서 값을 확정한다. 그 전에는 기본 30 으로 둔다.
- **리허설 결과 `credsDecrypted == 0`**: 라이브 `CRED_ENC_KEY` 를 정확히 넘겼는지 먼저 확인한다. 키가 맞는데도 0 이면 CRED_ENC_KEY 손상 사고(기존 `decrypt_failed` 다수 이력)와 동일 증상이므로 **T3 를 통과시키지 말고 즉시 사용자에게 보고**한다 — 백업 문제가 아니라 라이브 데이터 문제다.
- **오디오 원본 백업 정책**: unresolved-4 가 미결이면 8.5 는 "비대상 선언 + 고지" 로만 작성하고 미러 대상에 오디오를 넣지 않는다. 넣을지 여부는 데이터 소실 리스크 수용 주체(사용자)의 결정 사항이다.
- **라이브 users 원본 수를 알 수 없어 리허설 (a) 판정이 불가**: 리허설 직전 라이브에서 `GET /api/admin/metrics` 또는 `sqlite3 $DATA_DIR/web/meetings.db "select count(*) from users"` 로 기준값을 먼저 기록한다([사용자 수행]). 기준값 없이 "일치 확인" 을 주장하지 않는다.
