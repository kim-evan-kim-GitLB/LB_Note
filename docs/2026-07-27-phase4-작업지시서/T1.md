### 구현 단계

> 행번호는 실측값이지만 **앵커는 반드시 심볼명**으로 잡는다(리베이스로 행이 밀린다).

1. **빌드 지문 배선.** `src/web/buildinfo.py` 를 만들고 `deploy/Dockerfile` 끝단(마지막 `COPY` 와 `EXPOSE` 사이)에 ARG/ENV 를 추가한다. compose `build.args` 와 `deploy/release.sh` 로 값을 주입한다. 개발 컨테이너에서는 env 미설정이므로 `""` 가 나온다(정상, 하위호환).

2. **스케줄러 last-run 기록.** `app.py` 의 4개 루프 — `_cleanup_loop`(138행), `_db_backup_loop`(167행), `_claude_cred_health_loop`(724행), `_stt_stall_watchdog_loop`(1059행) — 각각의 `try/except` 뒤(sleep 전)에 `_mark_scheduler_run("cleanup"|"db_backup"|"cred_health"|"stt_stall")` 를 넣는다. `time.monotonic()` 과 `dt.datetime.now(timezone.utc)` 를 함께 저장해 ageSec 와 ISO 를 모두 낼 수 있게 한다. `lifespan`(182행) 의 `create_task` 분기에서 실제로 띄운 kind 만 `_scheduler_enabled` 에 넣는다 — `cred_health` 는 `CRED_HEALTH_CHECK_ENABLED` 와 `USES_AGENT_CLI` 조합에 따라 기동하지 않으므로 "미기동"과 "멈춤"을 구분해야 한다.

3. **`_health_snapshot() -> dict` 추출 (이번 개정의 핵심, T2 의 선행 산출물).**
   `src/web/app.py` 에 **라우트 데코레이터 없는 모듈 레벨 함수** `def _health_snapshot() -> dict:` 를 만든다. 인자 없음, HTTP/Request 의존 없음, 예외를 밖으로 던지지 않는다(내부에서 잡아 `status`/`reasons` 로 환원). 라우트 밖에서 `from src.web.app import _health_snapshot` 로 임포트해 직접 호출 가능해야 한다 — T2 의 `_ops_health_watch_loop` 이 이 함수를 인프로세스로 호출한다.
   반환 스키마(기존 `/api/health` 키는 전부 포함):
   ```
   {
     "ok": <status == "ok">,            # 기존 키 유지, 값만 계산식으로 교체
     "status": "ok" | "degraded" | "error",
     "reasons": ["db_write_failed", "backup_stale", "scheduler_stale:cleanup", ...],
     "build": {"backendSha": "...", "frontendSha": "...", "builtAt": "..."},
     "db": {"writable": true, "ts": "<write_probe 반환 ISO>", "error": null},
     "backup": {"enabled": DB_BACKUP_ENABLED, "latest": "<파일명|null>", "ageSec": <float|null>},
     "schedulers": {"cleanup": {"enabled": true, "lastRunAt": "...", "ageSec": 12.3}, ...4종},
     "disk": maintenance.disk_usage(),   # 실패 시 기존대로 {} — 값 노출만, 판정 안 함
     "clean_backend": ..., "extract_backend": ..., "summarize_backend": ...,
     "stt_model": ..., "auth_users": ..., "claude_auth": ...   # 기존 health() 키 그대로
   }
   ```
   판정 규칙(이 규칙 외의 조건으로 degraded 를 만들지 말 것 — T2 가 이 문자열을 이벤트 키로 쓴다):
   - `error`: `store.write_probe()` 가 예외 -> `reasons=["db_write_failed"]`.
   - `degraded`: (a) `DB_BACKUP_ENABLED` 이고 `maintenance.db_backup_age_sec()` 가 None 또는 `HEALTH_BACKUP_MAX_AGE_SEC` 초과 -> `backup_stale`, (b) `_scheduler_enabled` 에 있는 kind 의 ageSec 가 해당 주기 x `HEALTH_SCHED_STALE_FACTOR` 초과 -> `scheduler_stale:<kind>`.
   - **`disk_high` 는 T1 이 생성하지 않는다.** 디스크 임계 env(WARN/ERROR 퍼센트·대상 경로)의 소유자는 T5 이며, T1 은 `disk` 필드에 `maintenance.disk_usage()` 원값을 **노출만** 한다. T5 가 `maintenance.classify_disk(...)` 를 만든 뒤 `_health_snapshot()` 에 해당 reason 을 추가하고 `tests/test_health.py` 의 관련 회귀 테스트를 갱신하는 것이 T5 의 작업이다(강제 규칙 5).
   - **예약어 주석 표기 규칙(T2 grep 판정과의 충돌 회피)**: 미래 reason 을 주석으로 남길 때 **밑줄 표기 `disk_high` 를 그대로 쓰지 말고 `disk-high(T5 소유, 실제 reason 문자열은 밑줄 표기)` 로 쓴다.** 근거: T2 수용 기준이 `grep -rn 'disk_high' src/` 로 "T1 단계에서는 아직 배선되지 않았음"을 판정하므로, 주석에 밑줄 표기가 있으면 정상 구현에서 T2 판정이 실패한다. T2 측도 판정을 주석 제외/배선 여부로 좁히기로 했으나(감사2), **두 조치는 중복 안전장치이며 T1 은 위 표기 규칙을 반드시 지킨다.** 코드가 실제로 만들어내는 reason 문자열 집합은 아래 3종뿐이다: `db_write_failed`, `backup_stale`, `scheduler_stale:<kind>`.
   - 부팅 직후(스케줄러 첫 사이클 전) `lastRunAt` 은 null 이며 이때는 `scheduler_stale` 로 판정하지 않는다(프로세스 시작 시각 기준 age 를 쓴다).

4. **라우트 `health()` 는 감싸기만.** `app.py:3252` 의 `@app.get("/api/health")` 함수 본문을 다음 3가지로만 축소한다 — (1) `snap = _health_snapshot()`, (2) 공개 투영 `_public_health(snap)`, (3) `strict` 처리.
   - 시그니처: `def health(strict: int = 0, response: Response = None) -> dict`.
   - **공개 투영(무인증 노출 축소)**: `/api/health` 는 무인증 공개 엔드포인트다(소비자 `deploy/bootstrap.sh:69`, `src/slack_bot/lbnote_client.py:101`). 따라서 공개 응답에는 `ok`, `status`, `reasons`, `build`, `db.writable`, `backup.enabled`/`backup.ageSec`, 그리고 **기존 키 전부**(`clean_backend`/`extract_backend`/`summarize_backend`/`stt_model`/`auth_users`/`claude_auth`)만 담는다. `backup.latest`(파일명), `disk`(total/used/free/percent), `schedulers` 의 타임스탬프는 **공개 응답에서 제외**한다 — 저장소가 PUBLIC 이고 :49152 가 LAN 에 열려 있어 운영 내부정보 노출 회귀가 된다. 전체 스냅샷은 신설 `GET /api/admin/health`(`Depends(require_admin)`, `admin_metrics` 와 동일 패턴)에서만 반환한다.
   - HTTP 코드: `strict` 미지정이면 항상 200(기존 소비자 하위호환). `strict=1` 이면 `status=="error"` 일 때만 503, `degraded` 는 200. compose healthcheck 는 `?strict=1` 을 쓴다 — degraded 로 컨테이너가 unhealthy 로 플랩되지 않게 하기 위함이며, `restart: unless-stopped` 라 unhealthy 가 재시작을 유발하지 않는다는 사실을 주석으로 남긴다.

5. **write probe 안전성.** `write_probe` 는 `health_probe` 단일 행만 갱신하고 다른 테이블을 건드리지 않는다. 헬스가 30초마다 호출되므로(compose healthcheck) 쓰기는 1행 UPSERT 로 제한하고 `_lock` 점유가 짧음을 주석에 남긴다. 락 순서 규약(`store.py:220` 주석: 잡 스레드는 `_stt_semaphore` 보유 중 `_lock` 을 잡지 않는다)을 위반하지 않는다.

6. **지표 스크립트.** `tools/ops_metrics_snapshot.py` 를 작성하고 개발 DB(`output/web/meetings.db`, 실측 users 57 / meetings 5)로 동작을 확인한다. 읽기전용 URI 강제 — 라이브에서 실행되므로 쓰기 경로가 있으면 안 된다.

### 하위호환 / 롤백

- `/api/health` 는 **기존 키를 하나도 제거하지 않는다**. `ok` 만 상수 True -> 계산값으로 바뀌며, 기존 소비자 2곳(`src/slack_bot/lbnote_client.py:101` 의 `health()`, `deploy/bootstrap.sh:69`)은 HTTP 200 여부만 보므로 영향 없다. `src/slack_bot/handlers.py` 의 `handle_status` 도 예외 여부만 본다.
- 신규 필드(`build`/`db`/`backup`/`status`/`reasons`)는 **추가**만이므로 기존 파서를 깨지 않는다. 반대로 `disk`·`schedulers`·`backup.latest` 는 공개 응답에 **넣지 않는다** — 현재 공개 health 에 없던 정보이므로 이것도 하위호환이다(admin 경로에서만 노출).
- `strict` 미지정 시 응답 코드는 항상 200 — degraded 로 compose healthcheck 가 unhealthy 로 넘어가지 않는다. `error`(DB 쓰기 불가)일 때만 503 이며, 이는 이미 서비스 불가 상태다.
- `health_probe` 테이블은 `CREATE TABLE IF NOT EXISTS` 추가만이라 기존 DB 를 파괴하지 않고, 롤백(이전 이미지) 시에도 남아 있는 채로 무시된다.
- Dockerfile ARG/ENV 는 기본값 `""` — 빌드 인자를 안 넘겨도 빌드가 실패하지 않고 `build.*` 가 빈 문자열로 나온다(개발 컨테이너 실행 동일).
- `image: meetscript-ai:${IMAGE_TAG:-171}` 은 변수 미지정 시 기존 태그와 동일하므로 기존 배포 명령(`docker compose --env-file .env.deploy up -d --build`)이 그대로 동작한다.
- 코드 롤백 단위: 이 PR 은 `deploy/` + `src/web/{app,store,maintenance,buildinfo}.py` 로 국한되고 파괴적 마이그레이션이 없어 이전 이미지 기동만으로 완전 복귀한다.

### 후속 브랜치를 위한 인계 (인터페이스 계약)

- **T2 가 소비**: `from src.web.app import _health_snapshot` -> `{"status","reasons",...}`. T2 는 이 함수를 호출만 하고 판정 규칙을 바꾸지 않는다. **T1 머지 시점에 코드가 실제로 생성하는 `reasons` 문자열은 3종뿐**: `db_write_failed`, `backup_stale`, `scheduler_stale:<kind>`. 네 번째 예약 reason(디스크, T5 소유)은 T1 소스에 **밑줄 표기로 등장하지 않는다** — 주석 표기는 `disk-high(T5 소유)` 로 쓴다(구현 단계 3 참조). T2 는 이 사실을 전제로 "미배선" grep 판정을 배선 여부로 좁혀 쓴다.
- **T5 가 채움 + 테스트도 T5 가 고친다**: 디스크 임계 env(WARN/ERROR 퍼센트, 대상 경로 목록)와 `maintenance.classify_disk(...)` 판정은 전적으로 T5 소유이고, T1 은 `_health_snapshot()["disk"]` 로 `maintenance.disk_usage()` 원값을 노출만 한다. **`disk_high` reason 을 `_health_snapshot()` 에 편입하는 구현과, 그로 인해 기대값이 바뀌는 `tests/test_health.py::test_disk_high_not_owned_by_t1` 갱신은 T5 브랜치에서 T5 가 수행한다**(강제 규칙 5 — T5 에게 허용된 유일한 T1 테스트 수정 범위). T1 은 그 테스트를 "T5 가 갱신할 예정" 이라는 docstring과 함께 남기며, T5 는 이 편입을 하지 않으면 디스크 99% 에서도 health 가 영구 `ok` 로 남아 T2 카탈로그·T7 14장의 기술이 거짓 보증이 된다.
- **T3 가 소유**: `maintenance.run_db_backup()` 의 시그니처·반환 dict. T1 이 추가하는 `latest_db_backup`/`db_backup_age_sec` 는 읽기 전용 조회 함수라 그 계약과 충돌하지 않는다.
- **공유 파일 충돌 지점(리베이스 시 확인)**: `deploy/docker-compose.yml` — T1(image 태그·build.args·healthcheck strict=1) / T3(volumes 미러 바인드·environment) / T4(logging 3서비스). `deploy/.env.deploy.example` — T1·T2·T3·T4·T5. 실행 순서 T1 -> T2 -> T3 -> T4/T5 이므로 **T1 이 먼저 머지되고, 뒤 브랜치는 main 재동기 후 자기 줄만 얹는다.**

- **`_health_snapshot()` 을 만들었는데 순환 임포트가 나는 경우**: 판정 로직을 `app.py` 밖(예: 신규 모듈)으로 빼고 싶어질 수 있으나 **위치를 바꾸지 말 것** — T2 지시서가 `src.web.app._health_snapshot` 경로를 선행조건으로 못박았다. `app.py` 안에서 지연 임포트로 해결하고, 그래도 불가하면 사용자에게 보고해 T1/T2 양쪽 지시서를 동시에 고친다.
- **degraded 판정에 디스크를 넣고 싶어지는 경우**: 넣지 않는다. T5 가 임계를 확정하기 전에 T1 이 90% 같은 임시값을 박으면 Slack(WARN 80)과 health(ok) 가 갈리는 "진실 둘" 상태가 된다. 08-03 지표 리뷰에서 T5 가 임계를 확정한 뒤 T5 브랜치가 `disk_high` 를 추가한다.
- **compose healthcheck 를 `strict=1` 로 바꾼 뒤 라이브에서 unhealthy 가 뜨는 경우**: 원인이 DB 쓰기 실패이므로 임의로 판정을 완화하지 말고 즉시 롤백 절차를 발동하고 사용자에게 보고한다.
- **릴리스 태그 SHA 와 `/api/health` 값이 불일치**: 프론트 빌드 컨텍스트(compose `build.additional_contexts.frontendsrc` = `${FRONTEND_DIR}`)가 `/home/evan/LB_Note-web` 이 아닌 다른 경로를 보고 있을 가능성이 가장 크다(기본값이 `/home/evan/meetscript-ai` 로 남아 있다). `.env.deploy` 의 `FRONTEND_DIR` 확인은 [사용자 수행] 이며, 에이전트가 호스트 파일을 읽을 수 없으므로 추측으로 코드를 고치지 말고 값을 받아온다.
- **T1b Claude 자격증명 미확보**: 임시 우회를 코드로 만들지 말고 위 대체 판정으로 닫는다. 운영 LLM 자격증명 경로(Console API key / Teams seat / per-user 구독 토큰)는 unresolved-2 로 사람 결재 사항이다.
- **저장소 공개 여부(unresolved-1)가 미결인 상태**: 스모크 체크리스트에 `121.125.78.171`, `axlead1234` 를 그대로 넣지 말고 `<host>`, `<초기비번>` 플레이스홀더로 쓰고, 실제 값은 사용자가 로컬 결과 파일에만 채우게 한다. 같은 이유로 공개 `/api/health` 에 디스크·백업 파일명을 노출하지 않는다.
