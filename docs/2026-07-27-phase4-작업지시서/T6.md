### 구현 단계

1. **사전 정리(착수 시점 ruff 2건 -> 0건).** 게이트 스코프는 `src tests` 로 고정한다. 착수 직전 실측(2026-07-27 main): `sudo .venv/bin/python -m ruff check src tests` -> `Found 2 errors.` — `src/backends/_vendor/gtcrn/gtcrn.py:171` E711, `src/postprocess/handoff.py:22` F401. 이 2건의 처리 방침을 아래로 확정한다(둘을 섞지 말 것).
   - **(a) vendor E711 = 제외(수정 금지).** `src/backends/_vendor/` 는 외부에서 가져온 코드라 우리가 수정하면 다음 업스트림 갱신 때 diff 가 어긋난다. 제외는 **명령행 `--exclude src/backends/_vendor` 로만** 한다. `pyproject.toml [tool.ruff]` 에 `exclude` 를 넣지 않는 이유는 아래 표 마지막 행과 같다(Dockerfile 캐시 레이어 무효화). 실측 근거: `sudo .venv/bin/python -m ruff check src tests --exclude src/backends/_vendor` -> `Found 1 error.`(vendor 1건이 빠지고 handoff 1건만 남음).
   - **(b) handoff F401 = 개별 수정.** `src/postprocess/handoff.py:22` 의 `apply_corrections` 를 `from src.postprocess.glossary import (...)` 목록에서 제거한다. 파일 전체 미사용이고 `__all__` 재수출도 없음을 확인 완료(런타임 동작 불변, 아래 하위호환 절에 검증 명령 있음).
   - 정리 후 검증: `sudo .venv/bin/python -m ruff check src tests --exclude src/backends/_vendor` 가 **종료코드 0 이고 `All checks passed!` 를 출력**한다. (`Found 0 errors.` 라는 출력은 존재하지 않는다. `--output-format=concise` 를 붙여도 위반 0건이면 `All checks passed!` 가 나온다 — 실측 확인.)

2. **워크플로 작성** — `.github/workflows/ci.yml`. 아래 골격을 그대로 사용한다.
   - 트리거: `pull_request: branches: [main]` + `push: branches: [main]`. **`pull_request_target` 금지**(공개 저장소).
   - `permissions: contents: read` 최상단 선언, `concurrency: {group: ci-${{ github.ref }}, cancel-in-progress: true}`, `timeout-minutes: 30`.
   - `runs-on: ubuntu-latest` (public 인 동안 self-hosted 금지).
   - env: `COHERE_MODEL_PATH: /nonexistent`, `CUDA_VISIBLE_DEVICES: ""`.
   - steps: `actions/checkout` -> `astral-sh/setup-uv` (`version: "0.11.17"` 로컬과 동일, `enable-cache: true`, `cache-dependency-glob: "uv.lock"`) -> `uv sync --frozen` -> **`uv run --frozen python -c "import torch, pytest, ruff"`(스텝 이름 `deps-sanity`)** -> `uv run --frozen ruff check src tests --exclude src/backends/_vendor` -> `uv run --frozen pytest -q`.
   - `deps-sanity` 스텝을 반드시 둔다. `uv sync --frozen` 만으로 dev 그룹(pytest/ruff)과 torch 가 함께 들어온다는 전제는 로컬에서 확인할 수 없다 — `uv.lock` 이 `conflicts = [cu121, cu128]` 을 선언하고 있어 extra 없는 해상도 결과는 러너 로그로만 최종 확인 가능하다. 이 한 줄이 "sync 는 성공했는데 정작 필요한 게 안 깔림" 을 pytest 실패로 위장시키지 않고 즉시 드러낸다.
   - **extra 를 붙이지 않는다**(`--extra cu128` 금지). cu128 은 GPU 휠이고 러너에 GPU 가 없다. 마커 없이도 torch 는 설치된다 — `uv.lock` 상 `accelerate`/`bitsandbytes` 의 base 의존으로 `torch 2.12.0`(PyPI)이 들어온다. 즉 dev 그룹(pytest, ruff)만 필요해도 torch 설치는 회피 불가하며, 이것이 T6 비용의 전부다.
   - 액션은 태그가 아니라 커밋 SHA 로 핀하는 것을 권장(공개 저장소 공급망). 태그 사용 시 그 이유를 런북에 남긴다.

3. **비용 실측 및 판정.** 첫 실행 로그에서 `uv sync` 스텝 소요와 캐시 저장 크기를 확인한다.
   - 참고 실측(로컬 `.venv`, cu128 기준): `torch` 1.2G + `nvidia/*` 5.0G, venv 전체 8.0G. 러너 디스크(약 20GB 여유)에는 들어가지만 콜드 실행은 수 분이 걸린다.
   - 판정 규칙 (a) **`deps-sanity` 스텝(`import torch, pytest, ruff`)이 첫 실행 로그에서 성공**해야 한다. 실패하면 extra 조합·lock conflicts 원인 규명을 하지 말고 **즉시 5단계 폴백(C)으로 확정**한다(원인 규명은 Phase 5 티켓).
   - 판정 규칙 (b): **워밍 상태(캐시 히트) 총 소요 15분 초과 또는 캐시 저장 실패 2회 연속** -> (A) 폐기하고 5단계 폴백으로 전환. `uv sync --frozen` 자체가 실패하면 로컬 `.venv` 를 건드리지 말 것(`uv sync --extra cu128` 이 작동 중 torch 를 깨뜨린 이력 있음 — CI 는 러너에서만 돌린다).
   - 로컬에서 `uv sync` 를 재현 시도하지 말 것. 검증은 러너 로그로만 한다.

4. **[사용자 수행] 푸시 -> PR -> 머지, 브랜치 보호 등록.**
   - 현재 `gh api repos/kim-evan-kim-GitLB/LB_Note/branches/main/protection` 은 404(Branch not protected)다.
   - GitHub Settings > Branches > Add rule(main): Require a pull request before merging + Require status checks to pass -> 체크 이름 `gate` 선택.
   - 등록 확인: `gh api repos/kim-evan-kim-GitLB/LB_Note/branches/main/protection --jq '.required_status_checks.contexts'` 결과에 `gate` 포함.

5. **폴백(C) pre-push 훅** — (A) 가 정책상 불가하거나 3단계 판정에서 탈락한 경우.
   - `.githooks/pre-push` 내용: 저장소 루트로 이동 후 `sudo .venv/bin/python -m ruff check src tests --exclude src/backends/_vendor` 와 `sudo COHERE_MODEL_PATH=/nonexistent CUDA_VISIBLE_DEVICES= .venv/bin/python -m pytest tests -q` 를 순차 실행, 하나라도 실패하면 비영(非零) 종료. `set -euo pipefail` 필수, 실행 권한 `chmod +x`.
   - 활성화(클론마다 1회, 커밋되지 않는 로컬 설정): `git config core.hooksPath .githooks`.
   - 한계를 런북에 명시: `--no-verify` 로 우회 가능하고 required status check 로 등록할 수 없다. 따라서 G5 의 "차단 실증"은 훅 차단 로그로 대체한다.

6. **부정 실증(게이트가 실제로 막는가).** `feature/171-ci-gate-negative` 브랜치에 의도적 위반 1건(예: `tests/test_web_contract.py` 상단에 미사용 import 추가)을 넣는다.
   - (A) 경로: [사용자 수행] 푸시 + PR 생성 -> 체크 실패 -> 머지 불가 확인 -> PR 닫고 브랜치 삭제.
   - (C) 경로: `git push` 가 훅에서 차단되는 출력 로그를 캡처.
   - 실증 후 위반 커밋은 main 에 남기지 않는다.

7. **런북 갱신** — `docs/2026-07-08-ops-deploy-runbook.md` 에 **`## 11. 회귀 게이트`** 를 **기존 마지막 장 뒤, `## 참고` 앞**에 추가한다. 제목 줄은 정확히 `## 11. 회귀 게이트` 로 쓴다(`## 8.` 로 쓰면 T3 의 8장과 충돌해 T7 의 중복 판정이 깨진다). 내용: 게이트 스코프 2개 명령, 로컬 재현 명령, 훅 활성화 명령, 채택 수단과 그 근거(정책 회신 내용 또는 타임박스 초과 사실), 긴급 시 우회 절차와 사후 복구 규칙.
   - 삽입 직후 자기 검증 2줄: `grep -c '^## 11\.' docs/2026-07-08-ops-deploy-runbook.md` -> `1`, `grep -o '^## [0-9]\+\.' docs/2026-07-08-ops-deploy-runbook.md | sort | uniq -d` -> 출력 0줄.

- `src/postprocess/handoff.py` 변경은 미사용 import 제거뿐이며 런타임 동작 불변. 검증: `sudo .venv/bin/python -m pytest tests/test_extract_handoff.py -q` 통과 + `sudo .venv/bin/python -c "import src.postprocess.handoff"` 종료코드 0.
- `.github/`, `.githooks/` 는 `deploy/Dockerfile` 의 COPY 대상(`pyproject.toml`, `uv.lock`, `src`, `prompts`, `config`, `deploy/entrypoint.sh`)에 포함되지 않으므로 배포 이미지에 아무 영향이 없다. 검증: `grep -n "^COPY" /app/deploy/Dockerfile` 에 `.github`/`.githooks` 부재.
- 롤백: 워크플로만 되돌리려면 `.github/workflows/ci.yml` 삭제 + [사용자 수행] 브랜치 보호에서 required status check 해제. 훅 비활성화는 `git config --unset core.hooksPath`. 어느 쪽도 애플리케이션 코드 롤백을 수반하지 않는다.
- 기존 테스트 격리 규약 불변: `tests/conftest.py` 가 `MEETSCRIPT_BLOCK_DEFAULT_DB=1` 을 수집 전에 설정하고 `DEFAULT_DB_PATH` 를 임시 경로로 패치한다. CI 에서도 이 규약에 의존하며 `output/web/meetings.db` 를 만들거나 건드리지 않는다.

### 막히면

- **저장소 공개 여부(unresolved-1)가 미결이면** self-hosted 러너를 검토조차 하지 말고 (A) 클라우드 러너로 진행한다. private 전환이 확정되면 self-hosted 재검토는 Phase 5 로 넘긴다 — 3주차에 러너 등록·시크릿 격리까지 하면 T7 을 못 끝낸다.
- **사내 코드의 클라우드 러너 실행이 정책상 불가 판정이면** 즉시 5단계 폴백(C)으로 전환하고, G5 완료조건을 "훅 차단 로그 1건"으로 대체한다는 사실을 런북과 완료 게이트 증거에 명시한다.
- **타임박스 8h 초과 또는 `uv sync --frozen` 이 러너에서 2회 연속 실패하면** 원인 규명을 중단하고 폴백(C)으로 확정한다. torch 를 base 의존에서 떼는 작업(`pyproject` 재편, web extra 신설, 지연 임포트)은 Phase 4 범위에서 명시적으로 기각됐다 — 여기로 확장하지 말고 Phase 5 티켓으로 남긴다.
- **`pytest` 가 러너에서만 실패하면**(로컬 baseline 전량 통과) 환경 의존 테스트가 새로 들어온 것이므로 게이트를 약화시키지 말고 해당 테스트를 사람에게 보고한다. **마커 분리(gpu/model 마커로 러너에서 제외)는 도입하지 않는다** — 실측(2026-07-27 main, `COHERE_MODEL_PATH=/nonexistent CUDA_VISIBLE_DEVICES=` 상태에서 367건 전량 통과)상 모델·CUDA 없이도 스위트가 통과하므로 분리할 대상 자체가 없다. 임의 재도입 금지.
- **"torch 설치가 무거우니 지연 임포트로 러너 설치량을 줄이자" 는 제안은 기각한다.** torch 는 우리 소스의 임포트 시점 문제가 아니라 `uv.lock` 상 `accelerate`/`bitsandbytes` 의 **base 전이 의존**이라 `uv sync --frozen` 이 무조건 설치한다. 소스에서 지연 임포트를 해도 러너 설치량은 1바이트도 줄지 않는다. 설치량을 실제로 줄이려면 `pyproject` 의 base 의존을 재편(web extra 신설 등)해야 하는데 이는 Phase 4 범위에서 명시적으로 기각됐다 — Phase 5 티켓으로 남긴다.
- **브랜치 보호 설정 권한이 없으면** 저장소 소유자 권한 문제이므로 사용자에게 에스컬레이션한다. 에이전트는 `gh api ... /protection` 에 쓰기를 시도하지 않는다.
