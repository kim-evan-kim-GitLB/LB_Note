# 영어 전사 드리프트 진단 — 원인·기각된 가설·적응형 재디코딩 (2026-08-04)

대상: `samples/음성 260707_172619.m4a` (56.3분, 48kHz 스테레오 AAC)
증상 신고: **전사 일부가 영어로 나오고, 액션아이템·요약본이 생성되지 않는다.**

결론부터: **두 증상은 원인이 다르다.** 전사는 음향+청크 길이 문제이고, 요약 미생성은 이 음원의
내용 탓이 아니라 실행 환경 문제다. 아래 판정은 전부 개입 실험으로 확인했고, 초기 결론 중
4건은 적대적 검증에서 뒤집혀 수정했다.

---

## 1. 증상 계량

파이프라인 재실행 → 127 청크. 청크별 한글비율(한글/(한글+라틴)) 측정.

| 구간 | 청크 | 한글 | 라틴 | 한글비율 |
|---|---|---|---|---|
| 0-10분 | 25 | 1,980 | 645 | 0.754 |
| 10-20분 | 23 | 1,747 | 1,063 | 0.622 |
| 20-30분 | 20 | 844 | 1,375 | **0.380** |
| 30-40분 | 22 | 1,665 | 1,463 | 0.532 |
| 40-50분 | 23 | 1,951 | 660 | 0.747 |
| 50-60분 | 14 | 1,147 | 578 | 0.665 |

전체 문자 기준 한글비율 **0.617**. 회의 전체가 영어인 것이 아니라 특정 구간이 무너진다.

언어 게이트 기준: 제외 12건(5.3분, 9.6%) / 저신뢰 21건(9.7분, 17.4%) / 정상 94건(73.1%).

영어 부분은 의미 있는 영어가 아니라 **한국어 발음을 영어 철자로 옮긴 음차**다.
`Elbido`=LB도, `chojang`=출장, `Kujongan`=구정안. **실제 발화는 존재하고 모델이 한국어로
받아쓰지 못한 것**이다.

## 2. 기각된 가설

대상: 영어 우세 청크 8건. `max_new_tokens=479`(운영과 동일).

### A. 언어 힌트 누락 — 기각 (확정)

모델 문서에 "이 모델은 언어를 자동 감지하지 않으므로 language 지정이 필수"라고 되어 있어
가장 먼저 의심했다. 실행 경로를 끝까지 추적한 결과 디코더 프롬프트가 정상 생성되고 있었다.

```
processor.get_decoder_prompt_ids('ko')
  -> ['▁','<|startofcontext|>','<|startoftranscript|>','<|emo:undefined|>',
      '<|ko|>','<|ko|>','<|pnc|>','<|noitn|>','<|notimestamp|>','<|nodiarize|>']
  (en 을 주면 110 -> 62 로 토큰이 실제로 달라짐 = 무시되지 않음)
```

**주의**: 이 안전은 얇다. 모델 디렉토리에 함께 있는 remote code 버전 프로세서
(`models/cohere-transcribe-03-2026/processing_cohere_asr.py:488`)는 `language` 를
`**kwargs` 로 조용히 삼키고 `decoder_input_ids` 를 만들지 않는다. `src/backends/cohere.py:67`
이 native 클래스를 직접 import 하기 때문에 무사한 것이다 — `trust_remote_code` 로 바꾸면
언어 강제가 통째로 사라진다.

### B. 배치 패딩 — 주원인 아님

패딩이 전혀 없는 단일 디코딩에서도 8건 전부 영어였다. 단 문장 단위로는 배치 구성에 따라
출력이 달라진다(8건 중 완전일치 3건).

### C. repetition_penalty 조정 — 기각

| 조건 | 평균 한글비율 | 0.15 미만 | 산출물 성격 |
|---|---|---|---|
| 배치 + rp 1.2 | 0.037 | 7/8 | 영어 음차 |
| 단일 + rp 1.2 | 0.034 | 8/8 | 영어 음차(동일) |
| 단일 + rp 1.0 | 0.404 | 4/8 | **4건 영어 유지, 4건 반복 붕괴** |
| 배치 + rp 1.0 | 0.404 | 4/8 | 동일 |

rp=1.0 산출: `"네, 네. 네, 네..."` / `"그. 그. 그."` / `"츄르, 츄르..."`.
한글비율만 오르고 정보량은 0에 가깝다. **한글비율만 보면 오독한다.**

### D. WPE 디리버브 재활성화 — 부분 효과, 해결 아님

평균 한글비율 0.037 → 0.164, 그러나 0.15 미만은 7/8 그대로. 한 건이 한국어가 됐는데 내용은
`"네, 그리고 저희는 지금 이 영상을 보고 있습니다..."` — 자막 학습데이터 상용구 환각이다.
**언어 게이트는 이것을 못 잡는다**(한글비율 1.00). 게이트는 언어를 볼 뿐 사실 여부를 보지 않는다.

의미 있는 사실: **디코딩 설정을 안 바꾸고 음향만 바꿔도 출력이 달라진다** = 원인이 음향 쪽.

### E. 그 밖에 검정하고 배제한 것

- **장시간 누적 열화**: 한글비율 vs 시각 상관 r=+0.008. 구간별 드리프트 수 균등.
- **스테레오 다운믹스 상쇄**: 좌우 채널 상관이 드리프트 구간에서 오히려 더 높다(0.640 vs 0.557).
- **max_new_tokens 캡(479)**: 실제 최대 출력 139토큰, 캡 도달 0건. 드리프트 청크가 오히려 토큰이 적다(77.4 vs 81.3).

## 3. 원인 — 어려운 음향 + 긴 청크

### 어떤 구간이 무너지는가 (드리프트 17건 vs 정상 65건)

| 측정 | 드리프트 | 정상 | 해석 |
|---|---|---|---|
| VAD 발화 커버리지 | 0.748 | 0.858 | 말이 차지하는 비중이 낮음 |
| 청크 내 총 무음 | 6.97초 | 3.79초 | **1.8배** |
| 최대 무음 갭 | 1.87초 | 1.10초 | 끊긴 발화 |
| 평균 레벨 | -31.4 dB | -29.1 dB | 약간 더 작음 |
| 스펙트럼 롤오프(95%) | 4,082 Hz | 2,828 Hz | 광대역 잡음 많음 |
| 음성대역(300-3400Hz) 비중 | 0.410 | 0.468 | 말보다 잡음 |

마이크에서 멀거나 화면을 보며 하는 설명처럼 말이 드문드문하고 잡음이 큰 구간이다.
이 녹음은 기존 검증 음원보다 전반적으로 조용하다(전체 RMS -29.2dB vs -25.1dB).

### 거기에 청크가 길면 통째로 무너진다

같은 오디오, 디코딩 단위만 축소:

| 디코딩 단위 | 드리프트 8건 | 0.15 미만 | 정상 대조군 6건 |
|---|---|---|---|
| 현행 약 30초 | 0.037 | 7/8 | 0.988 |
| 15초 분할 | 0.601 | 0/8 | 0.978 |
| **8초 분할** | **0.799** | **0/8** | 0.980 |

숫자보다 중요한 것은 **내용이 실제로 복원됐다**는 점이다.

- 30초: `그, concerning. So, 반은 수신자 정도? 네. Okay, do you know? Cool...`
- 8초: `그, 검색을 해서. 받는 수신자 정보 이런 거. 이렇게 이정혁 프로님을 넣고 메일을 발송하게 되면...`

앞 청크(12분26초)가 "회의록 저장, 연동된 외부 서비스"를 말하다 "So"로 끝나며 이탈한다.
8초 분할본은 그 맥락에 정확히 이어지는 내용과 참석자 이름까지 되살렸다.

**단 길이는 단독 원인이 아니다.** 전체 127청크에서 길이-한글비율 상관은 r=-0.153으로 약하다.
음향이 어려운 구간에서만 길이가 방아쇠로 작동한다.

## 4. 채택 — 적응형 재디코딩 (전역 축소는 기각)

전역으로 `target_sec` 을 낮추는 안은 **정답 텍스트가 있는 음원으로 교차검증해 기각**했다.

| 구성 | ax WER | ax CER | 비고 |
|---|---|---|---|
| 현행 30초 | 0.398 | 0.257 | 기준선 |
| 전역 15초 | **0.420** | **0.286** | 정상 음원 악화 → 기각 |
| **적응형 재디코딩** | **0.397** | **0.251** | 무해(미세 개선) |

전역 축소의 손해는 **한글비율로는 보이지 않는다**(ax 0.975 → 0.979). 정답 텍스트로만 드러난다.

### 구현 (`src/pipeline.py`, `src/chunker.py`, `src/langmetrics.py`)

1. 배치 디코딩 후 청크별 한글비율 측정
2. `STT_REDECODE_RATIO`(0.45) 미만 + `STT_REDECODE_MIN_CHARS`(40) 이상인 청크만 후보
   — 초기값 0.15(게이트 exclude 임계와 동일)는 "한글이 사실상 0"만 잡아 회색지대를 놓쳤다.
   0.45 재측정: 저신뢰 21→1건, 한글비 0.617→0.895, ax 회귀 없음(WER 0.397/CER 0.251 동일).
3. 후보가 전체의 `STT_REDECODE_MAX_FRACTION`(0.5) 초과면 통째로 건너뜀(실제 영어 회의 방어)
4. 후보 청크를 **VAD 무음 경계 기준** `STT_REDECODE_TARGET_SEC`(8초)로 재분할 → 한 번의 배치로 재디코딩
5. **개선됐을 때만 교체**(한글비율이 원본보다 높을 때). 판정 불가는 교체하지 않음

### 실측 효과 (문제 음원)

| 지표 | 기존 | 적응형 |
|---|---|---|
| 언어 게이트 제외 | 12건 / 5.3분 | **0건** |
| 저신뢰 표시 | 21건 | 16건 |
| 전체 한글비율 | 0.617 | 0.773 |
| 반복 붕괴 | 3건 | 2건 |
| STT 소요 | 7.93초 | 8.13초 (+2.5%) |

18개 청크 후보 → 76조각 재디코딩 → 18건 전부 교체. ax 음원에서는 1건만 발동(무해).

## 5. 요약·액션 미생성 — 별개 원인

같은 전사를 그대로 `run_meeting_core` 에 넣어 재현한 결과 **16개 안건 / 72항목 / 액션 6건**이
정상 생성됐다(약 15분 소요). 영어 드리프트가 있어도 게이트가 12건을 배제하고 21건을 저신뢰로
표시한 뒤 남은 73%로 정상 회의록이 나왔다. **콘텐츠는 원인이 아니다.**

### 자격증명 만료는 후보에서 강등

인증 오류(`AgentCLIAuthError`)는 삼켜지지 않고 전파되어 잡이 `error / claude_auth_expired`
로 끝난다. 그러면 **전사도 화면에 보이지 않는다.** 사용자가 전사는 봤다면 잡은 `done` 으로
끝난 것이므로 자격증명 만료는 대부분 배제된다(CLI 가 인증 오류를 stderr 가 아닌 stdout 으로
낸 좁은 경우만 예외).

### 남은 후보 4가지

| 후보 | 왜 증상과 맞는가 | 확인 방법 |
|---|---|---|
| 백엔드 설정 off | `WEB_SUMMARIZE_BACKEND` 기본값이 빈 문자열(off). import 시점 env 스냅샷이라 `.env` 파일은 근거가 못 되고 **프로세스 env** 가 진실 | `GET /api/health` 의 `summarize_backend` |
| PATH 에 claude 없음 | sudo 기동 시 npm 전역 bin 이 빠짐. 예외가 삼켜져 요약·액션만 조용히 비고 잡은 정상 종료 | 서버 stdout `claude 를 PATH 에서 찾을 수 없습니다` |
| 타임아웃 | 콜당 600초 × 재시도 2회 = 단계당 최대 1800초. 잡 전체 타임아웃 없음, 스톨 감시는 전사 단계만 | 서버 stdout `타임아웃(600s)` |
| **JSON 파싱 실패** | 요약·추출 모두 파싱 실패 시 **예외 없이 빈 결과** 반환. **로그에 흔적이 전혀 없다** | `calls=3` 인데 traceback 없음 |

주의: 감사로그의 `calls=3` 은 "요약이 실행됐다"가 아니라 **실행 전 계획된 호출 수**다.

## 6. 부수 발견

### 배치 경로의 조용한 타임스탬프 오정렬 (수정됨)

`DEFAULT_TARGET_SEC = 30.0` 과 모델 특징추출기의 내부 재분할 임계
(`max_audio_clip_s 35 - overlap_chunk_second 5 = 30.0`)가 **정확히 같다**. 코드 주석은
"35초 미만이면 재분할 없음"이라 되어 있지만 실제 임계는 30초다. 30초를 넘으면 출력 텍스트 수가
입력 청크 수보다 많아지고 `zip()` 이 **예외도 경고도 없이** 초과분을 잘라내 이후 모든 세그먼트의
타임스탬프가 어긋난다. `--target-sec 31` 이면 재현된다. 이번 실행은 최대 청크 29.990초로
10ms 차이로 통과했다.

→ `_assert_chunk_alignment()` 로 즉시 실패하도록 수정.

### 한글비율 지표 결함 (수정됨)

`h/(h+l) if h+l else 1.0` — **빈 문자열이 1.0(완벽한 한국어)** 이다. 40자 미만 세그먼트 7건이
전부 "정상"으로 집계됐고, 그중 하나는 27.7초 오디오에서 10글자만 나온 전형적 실패였다.

→ `src/langmetrics.py` 신설. 판정 불가는 `None`. `language_gate` 는 1.0 규약이 의도된
설계("개입하지 않는다")라 그대로 뒀다.

### transcript.md 헤더 오표기 (수정됨)

VAD 분할 모드인데 헤더에 고정 분할 기본값(`chunk=60.0s, overlap=10.0s`)이 찍혔다.
→ `vad/energy, target=30.0s, avg=26.26s`

### 언어 게이트 fail-open (미수정)

`partition()` 은 세그먼트에 `id` 가 없으면 판정을 건너뛰고 통과시킨다. CLI 산출물
`text.json` 에는 `id` 가 없어 그 파일을 게이트에 넣으면 전량 무판정 통과한다. 웹 경로는
`id` 를 부여하므로 운영 영향은 없지만 도구·실험 스크립트에서는 방어가 조용히 꺼진다.

### 문서-코드 불일치 (미수정)

`CLAUDE.md` 는 배치 크기 기본값을 8이라고 기술하지만 실제 `STT_BATCH_SIZE` 는 32다.
