## 2. 적대적 검증 결과

검증자 2팀에 초안을 넘겨 반증을 시도하게 했다. 아래는 **직접 재현해 확인한 것만** 남겼다.

### V1. 필러 제거는 이 저장소의 지표로 판정할 수 없다

`answer/ax_tf_클로바.txt`(10,075 토큰) 실측:

| 필러 | reference 내 단독 토큰 | 비중 |
|---|---:|---:|
| 음 | 0 | 0.00% |
| 어 | 7 | 0.07% |
| **그** | **138** | **1.37%** |
| (참고) 좀 | 104 | 1.03% |

Clova reference 는 필러를 제거하지 않는다. 음/어/그를 전량 제거하면 145 토큰이 삭제 오류가 되어
**WER 하한 +0.0144**. 진단에서 `target_sec` 전역 축소를 기각한 근거가 **+0.022** 였으므로
같은 자릿수의 악화를 **의도적으로** 만드는 셈이다.

구두점 정리는 아예 측정 불가다 — `scoring.py:23` 이 채점 전 구두점을 전량 제거한다.

### V2. "되살린다"가 아니라 신규 구현이다

```python
# stages/clean.py:172-188
groups = group_adjacent_segments(segments, self._group_chars)
for group in groups:
    for idx in group:                 # 그룹 안을 다시 개별 순회
        raw = backend.generate(...)   # 세그먼트당 1콜 그대로
```
같은 파일 주석이 이유를 밝힌다 — `"출력은 항상 1:1 로 유지"`. 1콜 N출력은 파싱·정렬 책임을
새로 만든다. STT 배치 경로에서 이미 같은 형태의 사고(조용한 타임스탬프 오정렬)가 났고
`_assert_chunk_alignment` 로 막았다. **정제 경로에는 그 방어가 없다.**

### V3. 정제가 GPU 슬롯을 쥔 채 LLM 을 호출한다

```python
# app.py:1251-1261
with _stt_semaphore:                     # GPU 슬롯 2개 중 1개 점유
    _set_phase(job_id, "transcribing")
    transcribe_to_segments(..., backend_name=CLEAN_BACKEND)
        └ service.py:178  clean_segments(...)   # 여기서 claude -p N콜
```
① STT 동시성 2가 실질 붕괴 ② LLM 동시성 상한 우회 ③ phase 고정으로 스톨 워치독
(`STT_STALL_SEC=900`) 오탐. `WEB_STT_STALL_MARK_ERROR=1` 이면 **정상 잡을 error 로 마감**한다.

### V4. 정제 실패가 잡을 죽이고 원인을 잘못 표시한다

core 실패는 삼켜지지만(`service.py:224`) 정제는 try/except 가 없다(`service.py:75-96`).
phase 가 `transcribing` 이라 `app.py:1319` 가 `stt_engine_error` 를 붙인다.
**8초 만에 성공한 전사를 통째로 잃고, 원인 표시까지 틀린다.**

### V5. 원문이 영구 소실된다

`web_contract.py:43` 이 `cleaned` 를 우선해 계약에 싣고 원문 필드가 없다.
`save_original_snapshot` 이 저장하는 "원본"은 **이미 정제된 본문**이다.
→ revert 를 눌러도 원문으로 돌아갈 수 없다. STT 는 비결정적이라 재처리로도 복원 불가.

### V6. 정제가 언어 게이트보다 먼저 돈다 — 방어를 조용히 무력화

순서는 `clean_segments` → `run_meeting_core` → `language_gate.partition` 이다.
게이트 임계는 **raw STT** 기준으로 캘리브레이션됐다(`language_gate.py:8-9`: 환각 cps 14.0~14.9).
정제는 간투사를 지워 `chars` 를 줄이므로 `chars_per_sec` 가 내려가
`LANG_GATE_MAX_CPS=12.0` 조건이 **안 걸린다**. 실측 diag 에서 `speech_rate_burst` 로 잡힌
세그먼트 2건(id 82, 98)이 이 경로로 빠진다.

더 나쁜 것은 정제 프롬프트가 "끊긴 발화 잇기"를 허용해 **환각을 더 그럴듯한 한국어로 다듬는다**는 점이다.

### V7. 저장소는 이미 다른 결론을 내려뒀다 — 다만 대안은 아직 없다

```
정제(CleanStage)는 segment당 1콜이라 하니스 오버헤드(~25k/콜)로 ≈$4~5/회의가 든다.
따라서 대량 정제를 클라우드로 돌릴 거면 직접 API 백엔드(anthropic/openai)나
로컬 백엔드(ollama 등)가 비용·결정성 면에서 유리하다.        — agent_cli.py:16-23
```

**정정**: 초안은 "대안이 이미 저장소에 있다"고 적었으나 틀렸다.
`AnthropicBackend.generate` 는 `NotImplementedError` 스텁이다(`backends/anthropic.py:29`).
대안은 **존재하는 게 아니라 구현해야 하는 것**이다. 그래도 결론은 같다 —
배치화보다 백엔드 교체가 먼저다(하니스 25k 소멸 + 병렬화 자유).

### V8. A3 는 목표와 반대로 작동한다 — 실측 시뮬레이션

`output/diag-260707/core-result.json` 기준:

|---|---:|---:|---:|---|
| 재디코딩 전 | 12 | 21 | 0.183 | low_quality 발동 |
| 재디코딩 전 + A3 | 0 | 33 | **0.260** | **보수 모드 심화** |

`low_conf_ratio ≥ CORE_LOW_QUALITY_RATIO(0.15)` 이면 `CASE_LOW_QUALITY` → `conservative=True` →
프롬프트가 **`"근거가 약하면 항목을 만들지 말고 비워라. 빈 요약·빈 액션은 정상 결과다"`** 를 받는다
(`meeting_profile.py:127-131`, `orchestrator.py:45-49`).

**즉 A3 는 "요약이 빈다"는 원래 문제를 악화시킨다.** 그리고 적응형 재디코딩이 성공한 경로에서는
exclude 가 0이라 **애초에 할 일이 없다**.

추가로: 요약은 저신뢰 단독근거를 드롭하지만(`summarize_schema.py:266`)
**액션아이템은 드롭하지 않고 flag 만 붙인다**(`orchestrator.py:343`).
영어 환각이 액션으로 **Slack DM·Google Docs 내보내기까지 나간다.** A3 는 이 통로를 넓힌다.

### V9. B1 의 검증식이 현재 기본값을 스스로 거부한다

native 특징추출기 코드 확인:
```python
# transformers/models/cohere_asr/feature_extraction_cohere_asr.py:305,310
fast_path_threshold_s = max(0.0, self.max_audio_clip_s - self.overlap_chunk_second)  # 30.0
if duration_s <= fast_path_threshold_s:      # 등호 포함 → 30.0 은 안전
```
초안의 "29.9 초과 거부"는 틀렸다. `DEFAULT_TARGET_SEC=30.0` 이 부팅 즉시 거부된다.
**올바른 조건은 `target_sec <= 30.0`** 이고, 임계는 상수로 박지 말고 모델 config 의
`max_audio_clip_s - overlap_chunk_second` 에서 읽어야 한다(모델 교체 시 조용히 틀어짐 방지).

### V10. A2 — 실제로 돌려본 결과 초안의 전제가 틀렸다

```
apply_corrections("Quan은 좋다. Quan 은 좋다.", {"Quan":"Qwen"})
  → 'Quan은 좋다. Qwen 은 좋다.'      # ASCII 키는 조사가 붙으면 미적용
apply_corrections("회의에서 회의록을 정리", {"회의":"미팅"})
  → '미팅에서 미팅록을 정리'          # 2자 키가 부분어 오염
apply_corrections("오늘 미팅 그리고 회의", {"미팅":"회의","회의":"미팅"})
  → '오늘 미팅 그리고 미팅'           # 순차 적용 → 연쇄/사이클
```

- **ASCII 키는 한글 조사 앞에서 죽는다.** `\b` 뒤에 한글이 오면 경계가 아니다.
  사용자가 영문 용어를 등록하면 조사 붙은 대다수가 조용히 무시된다("등록했는데 안 고쳐진다").
- **"키 2자 미만 금지"로는 부족하다.** 문제는 길이가 아니라 형태소 경계다.
- **연쇄 치환**: 규칙을 누적 출력에 순차 적용한다(`glossary.py:72-76`). 다중 사용자 사전을
  병합하면 A 의 정답 표기가 B 의 오답 키가 되는 사이클이 생긴다.

### V11. B2 는 통계도 안 보고 즉시 EXCLUDE 한다

`language_gate.py:104-105` 는 상용구 매칭 즉시 반환한다. 실측 세그먼트 길이는
**중앙값 158자, 최대 304자**(약 30초 발화)다. **문구 하나가 30초 분량의 실제 회의 내용을 통째로 지운다.**
영어 상용구는 한국어 회의에 나올 이유가 없어 단독 매칭이 정당했지만,
"이 영상을 보고 있습니다"는 화면공유·데모에서 **정상 발화**다.

### V12. `redecoded` 플래그가 후단에 도달하지 못한다 — 구현 잔여 결함

적응형 재디코딩은 `text.json` 에 `redecoded: true` 를 남기지만,
웹 경로의 `normalize_segments` 가 `{id,start,end,text}` 만 만들어(`schema.py:39-41`)
**게이트·관측·UI 어디에도 도달하지 않는다.** A3 재검토와 B4 의 전제 조건이다.

### V13. 파싱 실패 말고도 삼켜지는 지점이 4곳 더 있다

`orchestrator.py` 의 `traceback.print_exc()` 후 계속 진행하는 지점: **99(병렬 워커) · 298(localize) ·
435(reduce) · 461(critic)**. stdout 에만 찍히고 구조화된 신호가 없다.
B5 는 파싱 실패만이 아니라 이 넷을 전부 `coreMeta` 실패 카운터로 올려야 진단이 성립한다.

### V14. 손대려는 코드에 단위 테스트가 하나도 없다

`grep -rln "CleanStage|apply_corrections|group_adjacent_segments" tests/` → **0건**.
A1(정제)과 A2(사전)는 **테스트 없는 코드**를 건드린다. 두 항목 모두 착수 전 테스트 확보가 선행이다.

## 3. 확정 항목

### 1순위 — B5. 파싱 실패 관측성 <sub>SOUND (범위 확대)</sub>

**왜 1순위인가**: 요약 미생성 4후보(백엔드 off / PATH / 타임아웃 / 파싱 실패) 중
**파싱 실패만 현재 진단이 원리적으로 불가능**하다.

**설계**
1. `summarize.py:86`, `extract.py:139`, `critic.py:182` 의 `except` 에 audit 이벤트 추가
   (`event=stage.parse_failed stage=... backend=... len=... head=<앞 200자>`).
   **전문 저장 금지**(PII).
   함께 `orchestrator.py` 의 삼켜지는 4곳(99 병렬 워커 / 298 localize / 435 reduce / 461 critic)도
   `coreMeta` 실패 카운터로 올린다(V13).
2. **passthrough 의 정상 빈 결과와 실백엔드의 파싱 실패를 구분**한다. 백엔드 이름으로 분기.
3. **`_job_reason_hint` 의 `done` 분기를 고친다**(`app.py:1424`). 지금은 `done` 이면 무조건
   `None` 이라 "성공했는데 요약이 빈" 케이스가 정확히 이 분기로 빠진다 —
   **고치지 않으면 B5 는 효력이 없다.**
4. `calls` 카운터를 **계획치와 성공치로 분리**한다(`app.py:1560`). 분리하지 않으면 관측성을
   추가하고도 같은 착각을 반복한다.

**측정**: 잘린 JSON 을 반환하는 스텁 백엔드로 강제 실패 → 감사로그 1행 출현.
현재 검출률 0% → 100%.

**주의**: 진단에서 재현한 회의는 conservative 모드였는데도 요약이 정상 산출됐다
(agenda 16, actions 6). **"요약 미생성 = 파싱 실패"는 아직 가설**이다.
B5 는 그 가설을 검증하기 위한 것이지, 확정된 원인을 고치는 것이 아니다.

### 2순위 — B1. target_sec 노출 <sub>NEEDS_REVISION</sub>

`chunker.py:24` 상수이고 웹 경로는 30.0 고정이라 배포에서 조정할 방법이 없다.

**수정된 설계**
- 검증식은 **`target_sec <= 30.0`**(V9). 임계는 모델 `config.json` 의
  `max_audio_clip_s - overlap_chunk_second` 에서 읽는다.
- 검증을 **설정 로드 시점**으로 앞당긴다. `_assert_chunk_alignment` 는 런타임 최후 방어로 남기되,
  설정 실수 하나로 회의가 통째로 죽지 않도록 설정 단계에서 먼저 막는다.
- `chunker.py:25` 주석("< max_audio_clip_s(35)")을 30.0 으로 정정한다.
- **기본값 변경은 금지**(정상 음원 WER 0.398→0.420, 진단 §4).

### 3순위 — redecoded 플래그 관통 <sub>신규</sub>

`normalize_segments`(`schema.py:39-41`)가 meta 를 버려 재디코딩 여부가 후단에 도달하지 못한다.
게이트·관측·UI 가 이 정보를 쓸 수 있게 관통시킨다. 또한
`STT_REDECODE_MAX_FRACTION` 으로 건너뛴 경우의 `skipped_reason` 도 잡 결과까지 전달한다 —
지금은 "왜 안 살아났는지"를 운영에서 알 수 없다.

### 4순위 — B4. 게이트 결과 노출 <sub>NEEDS_REVISION</sub>

**문구를 고친다.** 게이트 제외는 **요약·추출 입력에서만** 빠지고 transcript 에는 그대로 남는다
(`web_contract.py:34-53` 은 게이트를 참조하지 않는다). "9.6% 제외"는
"내 회의록의 10%가 날아갔다"로 읽힌다.

→ **"요약·액션 생성에서 제외된 구간 12개(비한국어/음질) — 전사 본문은 그대로 있습니다"**
   + 해당 구간 점프 링크. 퍼센트보다 **개수 + 이동 링크**가 오해가 적다.

**배선이 필요하다**: `coreMeta` 는 감사로그로만 흐르고 잡 결과·DB 에 없다.
계약 필드 추가 + 재요약 경로 대칭 처리가 선행이다. 3순위 완료 후 착수한다.

**역효과 주의**: 적응형 재디코딩으로 제외 건수가 12 → 0 이 됐다. 대부분의 회의에서 배지는
"0건"만 띄우고, 어쩌다 뜨는 숫자는 근거 없는 불안을 만든다.
→ 총량 퍼센트 상시 노출이 아니라 **임계 이상일 때만**, 그리고 transcript 안에서
해당 구간을 인라인 마킹 + 타임스탬프 점프로 처리한다.

### 5순위 — A2. 사용자 사전 <sub>NEEDS_REVISION (전면 재설계)</sub>

V10 때문에 초안의 "키 길이 제한 + 미리보기"로는 부족하다.

**필수 요건**
- **1패스 동시 치환**: 단일 alternation 정규식 + 콜백. 순차 누적 적용을 버려 연쇄·사이클 제거.
- **저장 시점에 사이클 거부**.
- **ASCII 키에 한글 조사 lookahead 허용** — 안 그러면 영문 용어 등록이 대부분 무효다.
- **미리보기는 샘플이 아니라 해당 사용자의 실제 회의 코퍼스 전체**에 대해 매칭 건수·예시.
- **적용 시점 정의**: 치환은 적재 시 transcript 에 굳는다. 사용자가 사전을 등록하는 동기는 보통
  "지난 회의록도 고쳐지나?"인데, 소급 적용은 `evidence_seg_ids` 앵커를 깨뜨린다.
  **소급 미적용을 UI 에서 명시**한다.
- **owner 배선**: `clean_segments` 는 사용자 컨텍스트를 받지 않는다(`service.py:82`).
  잡은 백그라운드 스레드라 요청 사용자 컨텍스트가 없다. 관통 작업이 필요하다.
- **컴파일 캐시**: `_compile_rules` 가 세그먼트마다 재컴파일한다(`glossary.py:72`).
- **`glossary_version` 대체**: DB 병합으로 "100% 재현" 주장이 깨진다. scope+updated_at 해시로.
- 스키마 변경 전 **DB 백업을 배포 런북에 명시**(현재 자동 백업 없음).

마이그레이션은 `CREATE TABLE IF NOT EXISTS` 나열 방식이라 **신규 테이블 추가에 한해 안전**하다
(재기동 시 자동 생성, 구 이미지 롤백 시 무시). DB 는 host-dir bind 라 재배포로 유실되지 않는다.

**순서가 중요하다**: `glossary.py` 의 경계 규칙·연쇄 차단·ASCII 조사 버그를
**기존 파일 사전 상태에서 먼저 고치고 테스트를 붙인 뒤** DB 화한다(현재 테스트 0건, V14).
순서를 뒤집으면 사용자가 전사를 깨뜨리는 사전을 스스로 등록하게 된다.

## 5-2. 구현 결과 (5순위 사용자 사전, 2026-08-05)

범위는 사용자 확정으로 **전역 + 개인 병합**. 층위는 `config/glossary.ko.json`(씨앗) → `global`
(관리자) → `user`(개인), 뒤가 앞을 덮는다. DB 가 비면 종전과 완전히 동일하게 동작한다.

### 선행: `glossary.py` 결함 3종 수정 (테스트 0건 → 19건)

| 결함 | 원인 | 수정 |
|---|---|---|
| ASCII 키가 한글 조사 앞에서 미적용 | 파이썬 정규식에서 한글도 `\w` → `Quan은` 에 `\b` 경계 없음 | ASCII 단어문자만 경계로 보는 lookaround |
| 짧은 한글 키의 부분어 오염(`회의록`→`미팅록`) | 한글은 무조건 substring | **2음절 이하 키만** 앞뒤 경계 요구(조사·접미 화이트리스트) |
| 순차 적용에 의한 연쇄 치환 | 키마다 `sub()` 반복 | 전체 키를 **단일 교대 패턴**으로 1패스 |

**중간 회귀와 정정**: 경계 규칙을 모든 한글 키에 걸었더니 실전사 342세그먼트의 사전 적중 23건 중
**4건이 깨졌다**(`오퍼스별`→`Opus별`, `위스퍼라는`→`Whisper라는`). "애매하면 치환하지 않는다"가
실제로는 17% 손실이었다. 규칙을 짧은 키로 좁혀 재대조 → **구·신 동작 차이 0건**.
`_compile_rules` 가 세그먼트마다 재컴파일하던 것도 `lru_cache` 로 묶었다.

### 배선

- `glossary_terms` 테이블(`scope`/`owner`/`source`/`target`, `UNIQUE(scope,owner,source)`).
  기존 DB 에도 `CREATE TABLE IF NOT EXISTS` 로 자동 생성됨을 구 스키마 DB 로 실증.
- **접수 시점에 병합 사전을 확정해 잡 스레드로 넘긴다** — 잡 스레드엔 요청 사용자가 없고,
  처리 중 사용자가 사전을 고쳐도 그 회의 결과가 흔들리면 안 된다. 조회 실패 시 씨앗으로 폴백
  (교정 때문에 전사가 죽으면 안 된다).
- 재현성 스탬프를 `glossary-1.1+db:<내용해시8>` 로. 파일 버전만으로는 더 이상 재현을 보장 못 한다.
- 미리보기는 `find_matches()` 로 **실제 치환과 같은 규칙**을 쓴다(따로 세면 "미리보기 3건,
  실제 0건"이 되어 신뢰가 무너진다).

### 설계 초안에서 바꾼 것

**"저장 시점에 사이클 거부" → 경고로 완화.** 단일 패스 치환으로 바꾼 뒤로 연쇄·왕복이라는 실제
파손이 사라졌다. 남은 것은 "의도한 게 맞나" 수준이라 저장을 막을 근거가 못 된다. 결과가 없는
입력(빈 값·자기 자신 치환)만 400 으로 거부한다.

### 적대적 검증에서 나온 결함 3건 (전부 수정)

| 결함 | 실측 | 수정 |
|---|---|---|
| `source` 에 `/` 가 들어가면 **영영 삭제 불가** | `DELETE .../A%2FB` → 405 | 경로 파라미터 → 쿼리 파라미터 |
| 등록 개수 무제한 | 301건 등록 성공 | `GLOSSARY_MAX_TERMS=200`(저장 계층에서 차단, 기존 항목 수정은 계속 허용) |
| 용어 길이 무제한 | 5,000자 키 저장됨 | `GLOSSARY_MAX_LEN=40` |

### 통과한 검증

- 구 스키마 DB 자동 마이그레이션 / 관리자 엔드포인트 403(조회·삭제 모두)
- 사용자별 사전 격리 — 같은 `source`, 다른 `target` 을 6스레드 동시 3,000회 치환해도 오염 없음
  (`lru_cache` 키가 항목 튜플이라 사용자 간 공유되지 않음)
- 상한(200개)에서 치환 비용 **0.269ms/세그먼트** → 300세그먼트 회의 환산 81ms (STT 대비 무시 가능)
- **소급 미적용이 코드로 보장됨**: `_apply_glossary` 호출부는 STT/CLI 경로뿐이고 재요약·회의 수정
  경로에는 없다. `retroactive: false` 를 계약 필드로 못박아 UI 문구가 서버와 갈라지지 않게 했다.
- API 응답 키 ↔ 프론트 TS 인터페이스 필드 일치 확인(4개 엔드포인트 전부)

**미검증**: 프론트는 `tsc --noEmit` + `vite build` 통과까지만이다. 이 컨테이너에 DISPLAY 가 없어
브라우저 렌더·상호작용은 확인하지 못했다.

**검증 총계**: 전체 573개 테스트 통과(528 → 573, 신규 45 = 재디코딩 임계 2 + glossary 19 + web 24), ruff clean,
프론트 빌드 성공.

## 6. 이 문서가 남기는 교훈

초안의 1순위 항목이 기각됐고, 2개가 더 기각됐다. 네 가지가 겹쳤다.

1. **성공 지표를 먼저 확인하지 않았다** — 필러 제거는 이 저장소의 WER 로는 성공이 실패로 보인다.
2. **과거 결정을 찾아보지 않았다** — 정제를 끈 이유와 그때의 결론이 코드 주석에 남아 있었다.
3. **실행 순서를 보지 않았다** — 정제가 게이트보다 먼저 돈다는 사실 하나가 A1 의 안전성 전제를 뒤집었다.
4. **개선이 다른 지표를 어떻게 움직이는지 시뮬레이션하지 않았다** — A3 는 `lowConfRatio` 를 올려
   보수 모드를 심화시키고, 그 결과 원래 고치려던 문제를 악화시킨다.

다음 설계에서는 착수 전에 **(a) 성공 지표가 존재하는가 (b) 과거에 같은 판단을 한 적이 있는가
(c) 실행 순서상 무엇보다 먼저/나중에 도는가 (d) 이 변경이 다른 임계값을 어느 방향으로 미는가**
를 먼저 확인한다.
