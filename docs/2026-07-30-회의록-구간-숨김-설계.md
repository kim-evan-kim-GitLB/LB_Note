# 회의록 구간 삭제(숨김) 기능 설계 (2026-07-30)

요구사항: **회의록 요약 후, 전체 회의록에서 특정 시간대 구간을 골라 삭제할 수 있게 한다.**
시간대별로 분리된 각 항목에 마우스 호버 시 삭제 버튼이 뜨고, 누르면 그 구간이 회의록에서 빠진다.

확정된 방식(2026-07-30 사용자 결정):

- **소프트 삭제(숨김·복구 가능)** — `hidden` 플래그만 세우고 엔트리는 보존.
- 파급 범위 = **재요약 입력에서 제외 + 내보내기에서 제외**. (자동 재요약 트리거는 하지 않음.)

---

## 1. 현황 (변경 대상 코드)

| 위치 | 현재 동작 |
|---|---|
| `src/components/ReviewView.tsx:1550` (프론트) | `transcript[]` 를 timestamp 버튼 + textarea 로 렌더. **텍스트 인라인 편집만** 가능. 삭제 UI 없음 |
| `src/postprocess/web_contract.py:176` `validate_transcript_edit` | 저장본에 transcript 가 있으면 **엔트리 개수·timestamp·speakerId 불변** 강제. 위반 시 `TranscriptStructureError` → 422. 결과 엔트리는 저장본 베이스 + 검증된 `text` 만 교체(클라 임의 필드 무시) |
| `src/web/app.py:1921` `_validator` | 위 검증을 store 락 안에서 수행(TOCTOU 차단) |
| `src/web/app.py:1547` `_segments_from_transcript` | 저장본 transcript → 재요약 입력 pseudo-segment. **빈 text 만 스킵** |
| `src/web/meeting_doc.py:167` `_render_transcript` / `:282` `_plain_transcript` | 내보내기용 전사 렌더(HTML / 평문). 빈 text 만 스킵 |
| `src/web/store.py:113` `_ORIGINAL_FIELDS` | `transcript` 포함 → `POST .../revert` 로 원본 복원 가능 |

즉 **삭제는 지금 계약상 불가**(개수 불변)하므로 계약 완화가 선행 작업이다.

## 2. 계약 변경 (additive, 후방호환)

`TranscriptEntry` 에 필드 1개 추가:

```ts
export interface TranscriptEntry {
  speakerId: string;
  text: string;
  timestamp: string;
  segmentId?: number;
  edited?: boolean;
  hidden?: boolean;   // NEW: true = 회의록에서 제외(소프트 삭제). 없으면 false 취급
}
```

- **개수·timestamp·speakerId 불변은 유지한다.** 클라이언트가 바꿀 수 있는 필드를 `text` 에서
  `{text, hidden}` **화이트리스트**로 딱 하나 넓히는 것뿐이다. 위조 표면이 늘지 않는다.
- `hidden` 은 엔트리에서 **제거 가능**(=복구). false 로 오면 서버가 키를 지운다(저장본 군더더기 방지).
- `segmentId` 공간이 보존되므로 기존 `summary`/`actionItems` 의 `evidence_seg_ids` 앵커,
  타임스탬프 점프, 오디오 재생이 **하나도 깨지지 않는다**. 하드 삭제를 택하지 않은 이유가 이것이다.
- 레거시 회의(hidden 필드 없음)는 전부 `hidden=false` 로 동작 → 마이그레이션 불필요.

## 3. 백엔드 변경 지점

### 3-1. 편집 검증 완화 — `web_contract.validate_transcript_edit`

```
가변 필드 = {text, hidden}  (그 외는 저장본 old 에서 보존)
- hidden = bool(new.get("hidden"))  → truthy 만 True, 그 외 키 제거
- text/timestamp/speakerId/개수 규칙은 현행 유지
- edited 누적 규칙도 현행 유지(숨김만 바꾼 엔트리에는 edited 를 세우지 않는다)
```

`hidden` 토글은 "교정(edited)" 이 아니므로 **`edited` 배지와 분리**한다. 사용자에겐 "수정됨"과
"숨김"이 다른 사건이다.

### 3-2. 재요약 입력 제외 — `app.py:_segments_from_transcript`

```
for e in transcript: if e.get("hidden"): continue   # 숨긴 구간은 요약·액션 산출 입력에서 제외
```

- 전부 숨겨서 남는 segment 가 0이면 기존 경로대로 **400**(`"재요약할 transcript 가 없습니다."`).
- 결과적으로 숨긴 구간은 새 `summary`/`actionItems` 의 근거가 될 수 없다(입력에 없으므로
  `ground_summary` 가 자동으로 인용을 떨군다 — 추가 게이트 불필요).

### 3-3. 내보내기 제외 — `meeting_doc._render_transcript` / `_plain_transcript`

두 함수의 필터에 `not s.get("hidden")` 을 추가한다. 이 둘이 내보내기 전 경로를 커버한다:

- `render_template_values()["transcript"]` → 관리자 Docs 템플릿 `{{transcript}}` 치환
  (`app.py:2435`, **실사용 경로**)
- `render_meeting_html(include_transcript=True)` → 전사 포함 HTML(공용 API·테스트)
- PDF·Drive 는 위에서 만든 Docs 를 export 한 결과라 자동 반영. Gmail 본문·Slack·Jira 는
  요약/액션만 쓰므로 영향 없음.

### 3-4. API

**기존 `PATCH /api/meetings/{id}` 를 그대로 쓴다**(신규 엔드포인트 없음).

- 프론트는 이미 transcript 전체 배열 + `If-Match` 로 저장한다(낙관락·412·백업/undo 재사용).
- 대안으로 `POST .../transcript/hide {segmentIds[], hidden}` 전용 엔드포인트를 둘 수도 있으나,
  412 처리·백업·감사로그를 새로 배선해야 하므로 v1 에서는 채택하지 않는다.
- 감사로그: `observability.audit("transcript.hide", meeting_id=..., n=...)` 를 patch 경로에
  추가한다(숨김 개수 변화가 있을 때만).

## 4. 프론트 변경 (`meetscript-ai`)

1. **`src/types.ts`** — `TranscriptEntry.hidden?: boolean` 추가.
2. **`ReviewView.tsx` 전체 회의록 섹션**
   - 각 엔트리 컨테이너에 이미 `group/entry` 가 있으므로 **호버 시 우측 상단에 휴지통 버튼**
     (`opacity-0 group-hover/entry:opacity-100`)을 띄운다. 클릭 → 로컬 상태에서 `hidden=true`.
   - 숨김 엔트리 표기: 카드를 접어 **1줄 미리보기 + 취소선 + "숨김" 배지 + 되돌리기 버튼**.
     textarea 는 비활성(숨긴 걸 편집할 이유가 없다).
   - 섹션 헤더에 **"숨긴 구간 N개 · 표시/감추기" 토글**. 기본은 접힌 상태로 목록에 남긴다
     (완전히 안 보이면 되돌릴 방법을 못 찾는다).
   - 저장은 **기존 transcript 저장 흐름 재사용**(`saveTranscript` + If-Match). 즉시 PATCH 하지
     않고 텍스트 교정과 동일하게 "저장" 액션에서 함께 반영 → 실수해도 저장 전엔 원복 가능.
   - 저장 성공 후 **재요약 유도 배너**: "숨긴 구간이 반영된 요약·액션아이템이 필요하면
     AI 재요약을 실행하세요." (자동 실행 금지 — GPU/비용 점유는 사용자 선택.)
3. **다중 삭제**(선택 범위): v1 은 항목 단위. shift+클릭 범위 선택은 후속(§7).

## 5. 엣지케이스

| 케이스 | 처리 |
|---|---|
| 기존 summary 가 숨긴 구간을 근거로 갖고 있음 | **그대로 둔다**(무파괴). 재요약 전까지는 어긋날 수 있음 → §4 배너로 안내. 타임스탬프 점프는 오디오·segmentId 가 살아있어 정상 동작 |
| 모든 구간을 숨김 | 저장은 허용(사용자 자유), 재요약은 400 |
| 클라이언트가 `hidden` 에 문자열·객체 주입 | `bool()` 정규화로 흡수(422 아님) |
| 레거시 회의(`hidden` 부재) | 전부 표시 — 기본값 처리로 마이그레이션 불필요 |
| 되돌리기 | (1) 저장 전 로컬 취소 (2) 저장 후 UI 복구 버튼 (3) `POST .../revert` 로 원본 transcript 복원 |
| 숨김 + 텍스트 교정 동시 patch | 독립 처리(둘 다 허용). `edited` 는 text 변경에만 세워짐 |
| Docs 템플릿을 이미 만든 회의 재변환 | 재변환 시점의 `hidden` 을 반영(저장본 기준) |

## 6-1. 구현 반영 델타 (2026-07-30 구현 시 추가 발견)

설계 시점에 못 짚었던 **숨김 누출 지점 2곳**을 프론트에서 함께 막았다:

- `ActionExtractionView.loadTranscriptFromMeeting` — 회의록 전문을 붙여넣기식 액션 추출 입력으로
  퍼올리는 경로. 숨긴 구간이 다시 추출 대상이 되므로 `filter(t => !t.hidden)` 추가.
- `ParticipantsView` 발화 통계 — 숨긴 구간은 발화 횟수 집계에서도 제외.
