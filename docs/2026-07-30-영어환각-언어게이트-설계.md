# 영어 환각 전사 대응 — 언어 게이트 + 요약·액션 프롬프트 고도화 설계 (2026-07-30)

요구사항: **WPE 전처리를 끈 뒤 영어로 전사되는 케이스가 늘고 있다. 이를 보완하기 위해 agent
요약·액션아이템 산출 core 로직을 고도화한다.**

확정 범위(2026-07-30 사용자 결정): **agent 프롬프트 강화 + 세그먼트 언어 게이트**.
영어 구간을 한국어로 되돌리는 번역 스테이지, STT 단계 재디코딩은 이번 범위에서 제외한다.

---

## 1. 원인 진단 (실측)

### 1-1. 언어 미지정 문제는 아니다

`src/backends/cohere.py:139/169/215` 에서 `language="Korean"` → `lang="ko"` 로 **이미 강제**되고
있고 `STT_LANGUAGE` 기본값도 `Korean` 이다. 즉 영어 출력은 언어 힌트 누락이 아니라
**무음·저SNR 구간에서 모델이 유창한 영어 문장을 지어내는 환각**(long-form 디코딩의 알려진 실패
모드)이다.

### 1-2. 실측: 환각 세그먼트는 정상 세그먼트와 뚜렷하게 분리된다

기존 산출물 3건을 계측했다(한글비율 = 한글 / (한글+라틴문자), cps = 텍스트 문자수 / 세그먼트 길이):

| 산출물 | 전처리 | 세그먼트 | 환각 영어 | 그 세그먼트 지표 |
|---|---|---|---|---|
| `output/asr_test/text-asr test.json` | WPE **off** | 121 | 1건 (start 1106.6s) | 한글비율 **0.01**, cps **14.9** |
| `output/asr_test_wpe/text-asr test.json` | WPE **on** | 121 | 1건 (start 1106.6s) | 한글비율 **0.00**, cps **14.0** |
| `output/verify/text-ax...음성파일.json` | WPE off | 215 | 1건 (start 3767.6s) | 한글비율 **0.00**, cps **14.2** |

정상 세그먼트 분포(같은 파일들):

- 한글비율 **최저 0.59**(영어 기술용어가 많은 발화: `"Action item, list를 도출해..."`,
  `"Whisper에 그 모델이 Tiny, Base, Small..."`)
- cps 중앙값 **6.7~7.7**, p90 **8.6~9.4**

→ 한글비율은 `0.01 vs 0.59`, cps 는 `14+ vs p90 9.4` 로 **양쪽에 넉넉한 마진**이 있다.
결정적(non-LLM) 규칙으로 잡기에 충분하다.

### 1-3. 주의 — 원인 귀속은 단정하지 않는다

같은 음원에서 **WPE on/off 둘 다 같은 구간에 1건씩** 나왔다. 즉 이 표본(2개 녹음)에서는
"WPE off 가 영어 환각을 유발한다"가 확인되지 않는다. 다만 표본이 좁아 현장 관측(빈도 증가)을
반박하는 근거도 아니다. **어느 쪽이든 게이트는 원인과 무관하게 유효**하므로, 원인 규명은
후속 과제로 분리한다(§7).

### 1-4. 현재 agent 로직에는 방어가 전무하다

- `prompts/summarize.ko.md`, `prompts/extract.ko.md` 에 **비한국어·환각 세그먼트 배제 규칙이 없다.**
  근거(`evidence_seg_ids`)만 달려 있으면 그대로 채택된다 → 환각 영어가 안건·액션아이템으로 승격 가능.
- **출력 언어를 한국어로 못박는 규칙도 없다** → 입력에 영어 비중이 커지면 영어 항목이 섞일 수 있다.
- `src/postprocess/validate.py` 의 게이트는 clean(정제) 단계 전용이고, 웹은
  `WEB_CLEAN_BACKEND=passthrough` 라 사실상 무검사로 통과한다.
- 그라운딩 게이트(`summarize_schema.ground_summary`)는 "근거 id 가 입력에 존재하는가"만 본다 —
  **그 근거의 품질은 보지 않는다.**

## 2. 설계 개요 (3층 방어)

```
STT segments
   |
   v
[1] 언어 게이트 (결정적, 신설 src/postprocess/language_gate.py)
      exclude  : 프롬프트에 아예 넣지 않음
      low_conf : 넣되 저신뢰 표시(~)
   |
   v
[2] 프롬프트 강화 (summarize.ko.md v1.1 / extract.ko.md v1.5)
      비한국어·환각·자막 상용구 배제 + 저신뢰 줄 단독근거 금지 + 출력은 항상 한국어
   |
   v
[3] 결정적 후처리 게이트 (ground_summary / extract 정규화)
      근거가 전부 저신뢰인 항목 -> 요약은 드롭 / 액션은 flag="확인필요"
```

LLM 의 선의에 의존하지 않는다: [2]가 실패해도 [1]과 [3]이 결정적으로 막는다.

## 3. [1] 언어 게이트 — `src/postprocess/language_gate.py` (신설)

```python
def segment_stats(text: str, start: float, end: float) -> dict:
    """{hangul, latin, hangul_ratio, chars, chars_per_sec} — 결정적 계측."""

def classify(text, start, end, *, phrases=HALLUCINATION_PHRASES) -> tuple[str, str | None]:
    """('ok' | 'low_conf' | 'exclude', reason)"""

def partition(segments: list[dict]) -> tuple[list[dict], dict[int, str]]:
    """(프롬프트 주입용 segments, {seg_id: reason}) — exclude 는 빠지고 low_conf 는 표시 플래그."""
```

판정 규칙(초기 임계값, §1-2 캘리브레이션 기준):

| 판정 | 조건 | 근거 |
|---|---|---|
| `exclude` (`non_korean`) | 한글비율 < **0.15** **그리고** 한글 문자수 < 5 | 실측 환각 0.00~0.01 / 정상 최저 0.59 → 마진 큼. 한국어 회의에서 한글이 사실상 0인 발화는 회의 내용으로 쓸 수 없다 |
| `exclude` (`speech_rate_burst`) | cps > **12.0** **그리고** 한글비율 < 0.5 | 실측 환각 14.0~14.9 / 정상 p90 9.4. 짧은 무음 구간에 긴 텍스트를 쏟는 환각 특성. 한글비율 조건을 AND 로 걸어 빠른 한국어 발화를 오탐하지 않는다 |
| `exclude` (`boilerplate`) | 자막·영상 상용구 정규식 매칭(`thank you for watching`, `subtitles by`, `please subscribe` 등) | 학습 데이터 유래 상용구는 회의 발화가 아니다 |
| `low_conf` (`mostly_non_korean`) | 한글비율 0.15 ~ **0.45** | 실측 정상 최저가 0.59 라 0.45 아래는 회색지대. 버리진 않고 표시만 |
| `ok` | 그 외 | |
| 공통 예외 | 반복 환각은 기존 `src/repetition.py` 신호를 재사용해 `low_conf` 가중 | 이미 있는 자산 |

- 임계값은 **`src/config.py` 노출**(`LANG_GATE_*`)해 코드 수정 없이 조정 가능하게 한다.
  `LANG_GATE_ENABLED=0` 으로 전체 비활성(안전 스위치).
- 모듈은 순수 함수 + 무의존(정규식/산술만) → 단위 테스트가 쉽고 GPU·LLM 비접촉.

### 배선 — `src/web/service.py`

`summarize_meeting()`(:132) / `extract_action_items()`(:96) 의 입력 구성부에 적용한다.

```
sum_input = [...]                                  # 현행
kept, gated = language_gate.partition(sum_input)   # NEW
summary = SummarizeStage().run(kept, backend)
summary = ground_summary(summary, kept, low_conf_ids=low_conf_ids(gated))   # NEW 인자
```

- `exclude` 세그먼트는 프롬프트에 **주입되지 않으므로** 그 id 를 인용하는 항목은
  `ground_summary` 의 기존 멤버십 필터가 자동으로 떨군다(추가 코드 불필요).
- `low_conf` 세그먼트는 주입하되 본문 줄 접두를 `[12]~` 형태로 표시한다
  (`extract_schema.transcript_with_ids` 에 `low_conf_ids` 옵션 추가).
- 두 함수는 초기 처리와 재요약(`app.py:1591-1595`)에서 공유되므로 **한 곳만 고치면 양쪽에 적용**된다.

## 4. [2] 프롬프트 강화

### `prompts/summarize.ko.md` → `summarize-ko-1.1`

추가 규칙(SYSTEM):

- **출력 언어**: 모든 `title`/`summary`/`text` 는 **한국어**로 쓴다. transcript 에 외국어가
  섞여 있어도 요약문은 한국어다(고유명사·기술용어는 원문 표기 유지).
- **오인식·환각 배제**: 회의 맥락과 무관한 외국어 문장, 같은 문구 반복, 영상 자막성 상용구
  ("thank you for watching" 등)는 STT 오인식/환각이다. **요약 대상이 아니며 인용하지 마라.**
- **저신뢰 표시 줄**: `[12]~` 처럼 `~` 가 붙은 줄은 인식 신뢰도가 낮다. 참고는 해도 좋으나
  **그 줄만을 근거로 하는 항목은 만들지 마라**(신뢰 줄 근거가 함께 있을 때만 채택).

### `prompts/extract.ko.md` → `extract-ko-1.5`

위 3개 규칙을 동일하게 넣고, 경계 예시 표에 2행 추가:

| 발화 | 판단 | 이유 |
|---|---|---|
| `[47]~ Okay, that's it. I have some room to be around the two girls...` | 제외 | 회의 맥락과 무관한 영어 = STT 환각. 액션 아님 |
| `[52] Action item list를 도출해서 문서로 만들기로 했어요` | 추출 | 영어 단어가 섞였을 뿐 한국어 발화 — 정상 액션 |

두 번째 행이 중요하다. **"영어가 보이면 버려라"로 과잉 일반화되면** 정상 기술 발화
(한글비율 0.59~0.66 구간)가 통째로 유실된다.

## 5. [3] 결정적 후처리 게이트

- `summarize_schema.ground_summary(summary, segments, low_conf_ids=None)`:
  유효 근거가 **전부** `low_conf_ids` 안에 있는 항목은 **드롭**. 요약은 항목 수가 많아
  드롭이 안전하다.
- `service.extract_action_items()`: 근거가 전부 `low_conf` 인 액션은 **드롭하지 않고**
  `flag="확인필요"`(`validate.FLAG_REVIEW`, 기존 상수 재사용)를 세워 사람 검토 큐로 보낸다.
  액션아이템은 유실 비용이 요약보다 크기 때문에 비대칭 처리한다.
- 관측성: 잡 로그·감사에 `language_gate {n_excluded, n_low_conf, reasons}` 를 남긴다
  (`observability.incr("langgate.excluded", n)`). admin 화면 노출은 후속.

## 6-1. 다중 agent core (2026-07-30 확정 — 구현 완료)

사용자 요구로 §2 의 3층 방어를 **다중 agent core** 로 확장했다. 단일 콜 하나를 잘 다듬는 대신,
케이스별 전문 agent 를 병렬로 돌리고 독립 검증 패스를 붙인다. 확정 사항:

- 구조: **라우터 + 병렬 전문 agent + critic 1패스**
- 대응 case: 영어 환각·무음 / 장시간(1시간+) / 다주제·다부서 / 저품질 전사 — **4종 전부**
- 시간 예산: **단일 콜의 2배 이내** → 모든 LLM 콜은 병렬(순차 실행 금지)

```
Stage 0  언어 게이트(결정적)        language_gate.partition
Stage 1  프로파일 + 라우팅(결정적)   meeting_profile.profile_meeting / route
Stage 2  전문 agent **병렬**        요약(창별) ∥ 추출(창별)
Stage 3  병합(reduce, 장시간만) + 검증(critic 1패스)
Stage 4  결정적 적용·그라운딩       판정 적용 -> ground_summary -> anchor 산출
```

### 케이스 판정을 LLM 에 맡기지 않는다

Stage 0·1 은 산술·정규식만 쓴다(한글비율·cps·세그먼트 수·길이·중복률). 그래서 재현성이 있고
라우팅 때문에 콜이 늘지 않는다. LLM 은 "이 회의를 어떻게 요약할까"를 결정하지 않고 각자 맡은
좁은 일만 한다. `multi_topic` 은 결정적 완전 판별이 불가해 **세그먼트 수를 프록시**로 쓰고,
프록시가 틀려도 프롬프트 강도만 달라지도록(산출이 깨지지 않도록) 설계했다.

### case -> 동작 매핑

| case | 판정 근거(결정적) | 동작 |
|---|---|---|
| `hallucination_risk` | 게이트 제외/저신뢰가 1건 이상 | critic 을 **엄격 모드**로(근거 불분명하면 keep 금지) |
| `long_form` | 40분 초과 또는 세그먼트 120개 초과 | 창 분할(겹침 3) -> 창별 **병렬** 요약 -> `reduce` agent 로 병합 |
| `multi_topic` | 세그먼트 80개 이상(프록시) | 안건 분리 강화 + **owner 본문앵커 추론 금지**(명시만 인정) |
| `low_quality` | 저신뢰 15%+ / 중복 30%+ / 전체 한글비율 저하 | **보수 모드** — 근거 약하면 항목을 만들지 말고 비운다 |

| 파일 | 역할 |

### 콜 수와 시간

| 회의 | 콜 | wall-clock |
|---|---|---|
| 40분 이하 | 요약1 + 추출1 (병렬) + critic1 = **3** | ≈ 단일 콜 + critic ≈ **1.3배** |
| 2시간(창 3개) | 요약3 + 추출3 (병렬) + reduce1 + critic1 = **8** | 창이 짧아 개별 콜이 빨라짐 → 단일 콜 대비 **2배 이내** |

콜당 `claude -p` 오버헤드(~25k 토큰)가 콜 수에 정비례하므로, 회의당 3~8콜이 비용 상한선이다.
`CORE_CRITIC_ENABLED=0` 으로 검증을 끄면 콜을 1개 줄일 수 있다.

### 판정과 적용의 분리

critic 은 **판정만** 한다(`keep`/`drop`/`flag` + 누락 보강 후보). 적용은 orchestrator 가 결정적으로:

- 요약 `drop` -> 항목 제거(요약은 항목이 많아 드롭이 안전)
- 액션 `drop` -> 제거 / `flag` -> `flag="확인필요"`(기존 사람검토 큐 재사용)
- 누락 보강 -> **근거(evidence_seg_ids)가 있는 것만** 채택, 그라운딩 후 합침
- critic 출력이 깨지면 판정 없음 = 전부 keep (검증 실패가 산출을 죽이지 않는다)

### 실패 격리

- 창 하나가 실패해도 나머지 창으로 계속한다.
- `reduce` 가 실패하면 **결정적 이어붙이기**로 폴백(중복 안건이 남을 수 있으나 유실 없음).
- 단, **인증 만료(`AgentCLIAuthError`)와 취소(`OperationCancelled`)는 병렬 워커에서 삼키지 않고
  전파**한다. 이 둘을 빈 결과로 묻으면 "재인증 필요"를 사용자가 알 수 없다.
- 병렬 워커는 `contextvars.copy_context()` 사본에서 실행한다 — 자격증명·취소 ContextVar 가
  새 스레드에 자동 전파되지 않기 때문이다(사본이 아니면 컨텍스트 재진입 오류).

### 배선 / 안전 스위치

- `service.enrich_to_contract`(초기 처리)와 `app._run_regenerate_job`(재요약)이 **같은 core** 를 탄다
  — 두 경로가 갈리면 "재요약하면 결과가 달라진다"는 혼선이 생긴다.
- `CORE_ENABLED=0` 이면 레거시 경로(요약 1콜 -> 힌트 -> 추출 1콜, 순차)로 즉시 되돌아간다.
- 관측성: `core.run` 감사로그(case·창 수·제외/저신뢰 수·총 콜 수·critic 드롭/플래그/보강 수).

- `tests/test_language_gate.py` 11건, `tests/test_agent_core.py` 19건 신규. **전체 451 passed**, ruff clean.
- 실측 회귀(`tools/bench_language_gate.py`, 457 세그먼트 = asr_test 121 + asr_test_wpe 121 + verify 215):
  **알려진 환각 3/3 탐지, 오탐 0/454, 저신뢰 0** -> `RESULT: PASS`
- 병렬성은 테스트가 직접 관찰한다(가짜 백엔드의 동시 진입 최대치 > 1).
- 짧은 라틴 조각(`"OK, LGTM"`)은 **버리지 않고 표시만** 한다 — 구현 중 발견한 결함으로,
  실측 환각은 365~427자였고 짧은 조각은 진짜 발화일 확률이 높다(`LANG_GATE_MIN_CHARS=40`).

## 7. 이번 범위에서 제외 (후속)

- **원인 규명**: WPE on/off · 무음 길이 · SNR 과 영어 환각 발생률의 상관을 여러 음원으로 측정
  (`src/quality.py` 의 SNR 지표 재사용). §1-3 의 미결 질문.
- **STT 단계 가드**: 저SNR·무음 청크 스킵 또는 재디코딩(`repetition_penalty` 조정 포함).
  WER 재검증 실험이 필요해 분리.
- **영어→한국어 복원 번역 스테이지**: 진짜 외국어 발화 회의를 살릴 수 있으나, 환각을
  그럴듯한 한국어로 정당화할 위험이 있어 채택하지 않았다.
